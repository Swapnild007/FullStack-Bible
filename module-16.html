MODULE 16 · DATA & SEARCH

Choose the right data engine for the problem.

Relational databases remain a core system of record. This module teaches when specialized document stores and search engines solve a different problem.

1. Relational vs document thinking

PostgreSQL is excellent when relationships, constraints, transactions and ad-hoc SQL matter. A document store can simplify data that naturally travels as one aggregate. Do not choose a database from a feature checklist; model the workload and correctness requirements first.

2. MongoDB concepts

Learn documents, collections, embedded documents, references, indexes and aggregation pipelines. Compare embedding versus referencing using access patterns, update frequency and consistency requirements. Understand replica sets and the operational meaning of distributed writes.

3. Search is not the same as your database

A primary database answers “what is the authoritative record?” A search engine is optimized for “find the records that best match this query.” Search indexes may be eventually consistent with the database, so your application needs a synchronization strategy.

4. Inverted indexes

Search engines commonly use inverted indexes: terms point to documents that contain them. Learn tokenization, normalization, analyzers, ranking, filters and facets. Typo tolerance is a product feature with relevance and latency tradeoffs, not magic.

5. Search products

Understand the roles of Elasticsearch, Algolia and Meilisearch. You do not need to memorize every API. Learn how indexing, querying, ranking, filtering, faceting, typo tolerance and synchronization fit together.

6. Synchronization patterns

  • Dual-write: simple conceptually, but a partial failure can leave stores inconsistent.
  • Outbox: persist the database change and an event together, then publish asynchronously.
  • CDC: stream database changes into downstream systems.
  • Rebuild: periodically recreate an index from the authoritative database.

7. Capstone — production search

Design search for the Learning Hub. Requirements: title/body search, filters by stage, typo tolerance, ranking, pagination, and near-real-time updates. Choose the search technology, define the index schema, synchronization strategy, failure recovery and rebuild process.
