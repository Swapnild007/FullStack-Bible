01

Computational thinking

Turn a real problem into something a machine can execute and measure.

What you are learning

Computational thinking is the discipline of decomposition, abstraction, representation and algorithmic reasoning. Before choosing a model, define the input, transformation, output, constraints and success criterion.

Core ideas

  • Decompose a large problem into smaller testable subproblems.
  • Separate the problem representation from its implementation.
  • Identify deterministic rules versus patterns that must be learned from data.
  • Specify measurable objectives and failure conditions.
Example: “Predict employee attrition” is not yet a technical specification. A useful formulation identifies an observation window, prediction horizon, eligible employees, features available at prediction time, target definition and evaluation metric.
Before moving on

Given a business problem, you can write its inputs, output, constraints, data assumptions and measurable success criterion without mentioning a model.

02

Python readiness

Build the programming foundation used throughout the Academy.

What you are learning

Python is the working language for the Academy, but the objective is engineering fluency rather than syntax memorization. You will learn data structures, functions, modules, exceptions, testing and the NumPy mental model.

Core ideas

  • Variables, types, conditionals, loops and comprehensions.
  • Lists, tuples, sets and dictionaries.
  • Functions, scope, modules and package structure.
  • Exceptions, logging, assertions and unit tests.
  • Vectorized numerical computation with NumPy.
import numpy as np x = np.array([1., 2., 3.]) y = 2*x + 1 print(y)
Before moving on

Write a small Python program without copying a template, test it, debug it and explain the data types and control flow involved.

03

Functions & algebra

The language in which ML relationships are expressed.

Build from first principles

A function maps inputs to outputs. Machine learning models are functions whose parameters are learned from data. You therefore need comfort with equations, coordinates, polynomials, exponentials and logarithms.

Core ideas

  • Sets, relations and functions.
  • Linear, polynomial, exponential and logarithmic functions.
  • Equations, inequalities and systems of equations.
  • Coordinate geometry and transformations.
  • Why logarithms appear in likelihoods, losses and numerical computation.
Worked idea: If y = 3x + 2, the coefficient 3 controls sensitivity to x while 2 shifts the function. A linear regression model generalizes this idea to many features: y = wᵀx + b.
Practice

Plot several functions, solve a small linear system and explain how changing each parameter changes the output.

04

Linear algebra

Vectors, matrices and transformations—the core language of modern ML.

What you are learning

Linear algebra turns collections of numbers into structured objects that can represent observations, parameters, transformations and learned representations.

Core ideas

  • Vectors, matrices, tensors and dimensions.
  • Dot products, norms, distances and angles.
  • Matrix multiplication and linear transformations.
  • Linear independence, span, basis, rank and null space.
  • Orthogonality, projections and Gram–Schmidt intuition.
  • Eigenvalues, eigenvectors and the motivation for PCA.
X = np.array([[1,2],[3,4]]) w = np.array([0.5, 2.0]) score = X @ w
Before moving on

You can determine matrix shapes before multiplying them and explain what a dot product and matrix multiplication mean geometrically and computationally.

05

Calculus & gradients

Understand how models know which direction to change.

Build the intuition

A derivative measures local change. A gradient collects partial derivatives with respect to many parameters. Optimization uses this information to change parameters so an objective improves.

Core ideas

  • Limits and continuity intuition.
  • Derivatives and partial derivatives.
  • Chain rule.
  • Gradient, Jacobian and Hessian concepts.
  • Local approximation and Taylor expansion.
  • Connection between gradients and backpropagation.
Simple derivation: for f(w) = (wx − y)², the derivative tells us how the error changes when w changes. Gradient descent repeatedly moves w in the opposite direction of that derivative.
Mini-lab

Implement finite-difference numerical gradients and compare them with an analytically derived gradient.

06

Probability

Reason mathematically about uncertainty.

Core ideas

  • Sample spaces, events and conditional probability.
  • Random variables and probability distributions.
  • Expectation, variance and covariance.
  • Joint, marginal and conditional distributions.
  • Bayes' theorem and posterior reasoning.
  • Binomial, Bernoulli and Gaussian distributions.
Why it matters: Classification can be viewed as estimating a conditional probability such as P(y | x). Bayesian reasoning asks how evidence changes belief about a hypothesis.
Practice

Construct a small probability table, calculate conditional probabilities and verify Bayes' theorem numerically.

07

Statistics

Move from data description to inference.

Core ideas

  • Population versus sample.
  • Mean, median, variance, standard deviation and quantiles.
  • Covariance and correlation.
  • Sampling distributions and the central limit theorem intuition.
  • Point and interval estimation.
  • Hypothesis testing, p-values and practical significance.
  • Simple regression and statistical assumptions.
Important distinction: a confidence interval is an inferential procedure, not a guarantee that a fixed unknown parameter has a stated probability of lying inside one particular computed interval.
Practice

Take a dataset, summarize it numerically and visually, estimate uncertainty, formulate a hypothesis and explain the result without confusing statistical and practical significance.

08

Optimization

Turn a learning objective into parameter updates.

Core ideas

  • Objective functions and feasible regions.
  • Gradient descent and learning rate.
  • Convex versus non-convex objectives.
  • Local minima, saddle points and convergence intuition.
  • Momentum and adaptive methods such as Adam.
  • Constrained optimization and Lagrange multiplier intuition.
w = 0.0 for _ in range(100): grad = 2*(w - 3) w -= 0.1*grad
Mini-lab

Change the learning rate, plot the objective over iterations and identify slow convergence, overshooting and stable convergence.

09

AI vs ML vs deep learning

Understand the hierarchy before choosing techniques.

AI is the broad field of building systems that perform tasks associated with intelligent behavior. Machine learning is a family of approaches that learn patterns or decision rules from data. Deep learning uses multi-layer neural networks to learn representations and functions.

Decision rule

  • If a precise rule is stable and known, conventional software may be enough.
  • If the mapping is difficult to specify but examples exist, ML may be appropriate.
  • If representation learning from large/high-dimensional data is valuable, deep learning may be appropriate.
Practice

Classify five real problems as rule-based software, supervised ML, unsupervised learning, reinforcement learning or generative AI and justify each choice.

10

Problem formulation

The model is downstream of the problem definition.

Ask these questions

  • What decision or prediction must be made?
  • At what exact time must it be made?
  • What information is available at that time?
  • What is the target and how is it measured?
  • What happens when the model is wrong?
  • What metric represents useful performance?
Example: “Predict churn” becomes a supervised classification problem only after defining the observation window, churn event, prediction horizon and eligible population.
Deliverable

Write a one-page ML problem specification before touching a dataset or model.

11

Data & target design

A mathematically sophisticated model cannot rescue a broken dataset.

Core ideas

  • Features, labels and observations.
  • Missingness and measurement error.
  • Data leakage and temporal leakage.
  • Train, validation and test partitions.
  • Sampling bias and class imbalance.
  • Feature availability at prediction time.
Leakage test: ask “Could this feature exist in production at the exact moment the prediction is made?” If not, it cannot be a legitimate training feature.
Practice

Take a real dataset and document its unit of observation, target, feature availability, missingness, split strategy and leakage risks.

12

Training vs inference

Separate learning from using a learned system.

During training, parameters are adjusted using a training objective. During inference, the learned parameters are applied to new inputs. This distinction affects data pipelines, latency, cost, security and monitoring.

Core ideas

  • Parameters versus hyperparameters.
  • Training data versus unseen data.
  • Offline training versus online inference.
  • Batch versus real-time inference.
  • Distribution shift between training and production.
Practice

Draw a complete training-to-inference pipeline and identify where data enters, where parameters change and where monitoring belongs.

13

Loss functions

Define mathematically what “wrong” means to a learner.

Core ideas

  • Squared error for regression.
  • Absolute error and robustness intuition.
  • Log loss / cross-entropy for classification.
  • Probabilistic interpretation of likelihood.
  • Per-example loss versus aggregate objective.
  • Regularization as part of an optimization objective.
Key distinction: the loss used to train a model and the metric used to judge whether it is useful need not be identical. The choice must reflect the learning problem and operational objective.
Mini-lab

Implement MSE and binary cross-entropy with NumPy, inspect their values for correct and incorrect predictions, and explain their behavior.

14

Model evaluation

Measure generalization, not memorization.

Core ideas

  • Train/validation/test methodology.
  • Accuracy, precision, recall and F1.
  • Confusion matrices and threshold selection.
  • ROC-AUC and precision-recall curves.
  • Regression metrics such as MAE, MSE and RMSE.
  • Calibration and uncertainty.
  • Cross-validation and model selection.
Metric choice: in a rare-event problem, accuracy can remain high while the model misses most positive cases. Evaluation must therefore be tied to the actual decision costs and data distribution.
Practice

Evaluate one classifier using a confusion matrix plus at least three appropriate metrics, then explain which metric should drive the operational decision and why.

15

Bias–variance

Understand why a model can fail by being too simple or too sensitive.

Bias captures systematic error from restrictive assumptions; variance captures sensitivity to the particular training sample. Generalization depends on controlling both rather than maximizing training fit.

Diagnose with evidence

  • High training error and high validation error can indicate underfitting.
  • Very low training error with substantially higher validation error can indicate overfitting.
  • Learning curves help separate data limitations from model limitations.
Practice

Train models of increasing complexity and plot training and validation error. Explain the region where additional complexity stops improving generalization.

16

Overfitting & regularization

Control complexity and improve generalization.

Core ideas

  • L1 and L2 penalties.
  • Early stopping.
  • Dropout.
  • Data augmentation.
  • Cross-validation.
  • Feature selection and dimensionality reduction.
  • More data and better data as alternatives to merely increasing regularization.
Important principle: regularization is not a magic switch. It changes the optimization problem so that certain parameter configurations become less attractive. The right amount must be established empirically on validation data.
Mini-lab

Fit an over-parameterized model, then compare no regularization, L2 regularization and early stopping using identical validation data.

17

Ethics & responsible AI

Technical capability must be accompanied by responsible deployment.

Core ideas

  • Fairness and disparate impact.
  • Privacy and data minimization.
  • Transparency and documentation.
  • Safety, robustness and abuse resistance.
  • Human oversight and accountability.
  • Security and access control.
  • Auditability and incident response.
Engineering question: “Can the model make this prediction?” is different from “Should the organization use this prediction for this decision?” Both questions belong in the system design process.
Before completing Stage 00

Write a short risk assessment for an ML system covering affected people, data risks, failure modes, fairness concerns, security threats, human oversight and monitoring.

Stage 00 completion assessment

Do not mark this stage complete because you have read the pages. Completion should require evidence that you can apply the foundation.

  • Implement a small numerical optimization algorithm from scratch.
  • Explain the linear-algebra shapes and operations in your implementation.
  • Perform a statistical analysis on a dataset and state uncertainty appropriately.
  • Formulate an ML problem with a defensible target, split and metric.
  • Train and evaluate a baseline model without leakage.
  • Diagnose underfitting/overfitting using evidence.
  • Write a responsible-AI risk assessment for the project.

Required mindset: derive → implement → test → explain → evaluate → document.
