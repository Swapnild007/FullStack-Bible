01

Computational thinking

Turn a real problem into something a machine can execute and measure.

What you are learning

Computational thinking is the discipline of decomposition, abstraction, representation and algorithmic reasoning. Before choosing a model, define the input, transformation, output, constraints and success criterion.

Core ideas

  • Decompose a large problem into smaller testable subproblems.
  • Separate the problem representation from its implementation.
  • Identify deterministic rules versus patterns that must be learned from data.
  • Specify measurable objectives and failure conditions.
Example: “Predict employee attrition” is not yet a technical specification. A useful formulation identifies an observation window, prediction horizon, eligible employees, features available at prediction time, target definition and evaluation metric.

First-principles lesson

Computational thinking begins before code. A computational formulation identifies a state, an input, an operation and an observable result. Decomposition reduces a large system into components whose contracts can be tested independently. Abstraction removes implementation detail while preserving the behavior that matters. Representation determines what the machine can efficiently manipulate: a table, graph, vector, image tensor or sequence can encode the same real-world concept in very different ways.

An AI problem adds another layer: uncertainty. A deterministic rule says exactly what to do for a given state; a learned system estimates a function from examples. This distinction matters because a prediction problem requires data, a target and an evaluation procedure, while a rules problem may require none of those.

Worked engineering method

Write the problem as input → transformation → output → decision. Then write constraints such as latency, cost, privacy and allowable errors. Finally define a measurable acceptance test. For an attrition system, for example, specify the prediction date, forecast horizon, eligible population, available features and action triggered by a prediction. Only then should you select an algorithm.

Mastery lab

Choose three business problems and produce a one-page specification for each. Include a system boundary, assumptions, edge cases, failure modes and a metric. Then challenge your own specification: identify one ambiguity that could cause two engineers to implement different systems.

Before moving on

Given a business problem, you can write its inputs, output, constraints, data assumptions and measurable success criterion without mentioning a model.

02

Python readiness

Build the programming foundation used throughout the Academy.

What you are learning

Python is the working language for the Academy, but the objective is engineering fluency rather than syntax memorization. You will learn data structures, functions, modules, exceptions, testing and the NumPy mental model.

Core ideas

  • Variables, types, conditionals, loops and comprehensions.
  • Lists, tuples, sets and dictionaries.
  • Functions, scope, modules and package structure.
  • Exceptions, logging, assertions and unit tests.
  • Vectorized numerical computation with NumPy.
import numpy as np x = np.array([1., 2., 3.]) y = 2*x + 1 print(y)

First-principles lesson

Python variables are names bound to objects, not typed memory boxes in the C sense. Expressions create or reference objects, and control flow determines which expressions execute. Understanding this model prevents subtle bugs involving mutability, aliasing and shared state. Lists and dictionaries are powerful because they provide high-level operations, but those operations still have computational costs.

Functions create explicit interfaces. Arguments enter a local namespace, a return value leaves it, and exceptions provide a separate control path for failure. Modules turn a script into reusable software. For AI work, this matters because notebooks are excellent for exploration but production systems need repeatable code, tests, dependency control and deterministic data preparation.

Under the hood

CPython compiles source into bytecode executed by a virtual machine. Reference counting and a cyclic garbage collector manage object lifetime. NumPy changes the performance model by storing homogeneous numerical data in contiguous buffers and performing many operations in optimized native code instead of executing a Python loop for every element.

Mastery lab

Build a small dataset loader with validation, logging and tests. Deliberately feed it malformed rows, missing values and wrong types. Your goal is not merely to make it run, but to make its failure behavior explicit and diagnosable.

Before moving on

Write a small Python program without copying a template, test it, debug it and explain the data types and control flow involved.

03

Functions & algebra

The language in which ML relationships are expressed.

Build from first principles

A function maps inputs to outputs. Machine learning models are functions whose parameters are learned from data. You therefore need comfort with equations, coordinates, polynomials, exponentials and logarithms.

Core ideas

  • Sets, relations and functions.
  • Linear, polynomial, exponential and logarithmic functions.
  • Equations, inequalities and systems of equations.
  • Coordinate geometry and transformations.
  • Why logarithms appear in likelihoods, losses and numerical computation.
Worked idea: If y = 3x + 2, the coefficient 3 controls sensitivity to x while 2 shifts the function. A linear regression model generalizes this idea to many features: y = wᵀx + b.

First-principles lesson

A function is a mapping from a domain to a codomain. In ML, a model is often written as f(x; θ), where x is an input and θ represents learned parameters. Algebra lets us manipulate these expressions, determine valid domains and reason about how changes in one quantity affect another. Linear, polynomial, exponential and logarithmic functions form a vocabulary that reappears in regression, probability, neural activations and optimization.

Logarithms are particularly important because they turn products into sums and make likelihood calculations numerically and conceptually manageable. Exponentials produce positive quantities and appear in softmax probabilities and exponential-family distributions. Understanding these transformations is more valuable than memorizing isolated formulas.

Worked derivation

For y = wx + b, changing w changes the slope while b translates the graph. With multiple features, y = wᵀx + b is the same idea expressed with a dot product. A useful exercise is to derive the output for two different vectors, inspect the contribution of each feature, and then ask what happens when features are measured in radically different units.

Mastery lab

Implement a function that evaluates linear, polynomial, exponential and logarithmic relationships. Plot them over useful domains, identify numerical regions where they become unstable, and explain those regions mathematically.

Practice

Plot several functions, solve a small linear system and explain how changing each parameter changes the output.

04

Linear algebra

Vectors, matrices and transformations—the core language of modern ML.

What you are learning

Linear algebra turns collections of numbers into structured objects that can represent observations, parameters, transformations and learned representations.

Core ideas

  • Vectors, matrices, tensors and dimensions.
  • Dot products, norms, distances and angles.
  • Matrix multiplication and linear transformations.
  • Linear independence, span, basis, rank and null space.
  • Orthogonality, projections and Gram–Schmidt intuition.
  • Eigenvalues, eigenvectors and the motivation for PCA.
X = np.array([[1,2],[3,4]]) w = np.array([0.5, 2.0]) score = X @ w

First-principles lesson

Vectors can represent points, directions, observations or parameter sets. A matrix can represent a collection of observations or a linear transformation. Matrix multiplication is not arbitrary multiplication: it composes transformations and computes weighted sums. Shape reasoning is therefore a core engineering skill. If X has shape n×d and w has shape d, then Xw has shape n and represents one score per observation.

Norms quantify magnitude, dot products quantify alignment, and projections express one vector in terms of another. Rank measures the number of independent directions represented by a matrix. These ideas explain redundancy, dimensionality reduction and why poorly conditioned systems can be numerically unstable.

Connection to ML

Linear regression, PCA, embeddings, attention and neural-network layers all use linear algebra. A dense neural layer is essentially a matrix multiplication followed by a nonlinear transformation. PCA can be understood through directions of maximum variance and eigenvectors of a covariance matrix, giving a concrete reason eigen concepts matter.

Mastery lab

Implement dot product, matrix multiplication and vector normalization first with Python loops and then with NumPy. Compare results, shapes and execution time. Explain why the vectorized version can be dramatically faster.

Before moving on

You can determine matrix shapes before multiplying them and explain what a dot product and matrix multiplication mean geometrically and computationally.

05

Calculus & gradients

Understand how models know which direction to change.

Build the intuition

A derivative measures local change. A gradient collects partial derivatives with respect to many parameters. Optimization uses this information to change parameters so an objective improves.

Core ideas

  • Limits and continuity intuition.
  • Derivatives and partial derivatives.
  • Chain rule.
  • Gradient, Jacobian and Hessian concepts.
  • Local approximation and Taylor expansion.
  • Connection between gradients and backpropagation.
Simple derivation: for f(w) = (wx − y)², the derivative tells us how the error changes when w changes. Gradient descent repeatedly moves w in the opposite direction of that derivative.

First-principles lesson

The derivative is a local rate of change. For a multivariable function, partial derivatives measure sensitivity to one coordinate while holding the others fixed; the gradient collects these sensitivities. The chain rule explains how derivatives propagate through compositions of functions. This is the mathematical foundation of backpropagation.

A gradient is not itself a direction of improvement. It points toward locally increasing function value. To minimize an objective, gradient descent uses the negative gradient. Step size determines how far the update moves. Too small can make optimization slow; too large can cause oscillation or divergence.

Worked derivation

For f(w)=(wx-y)², differentiating gives df/dw = 2x(wx-y). The factor x explains why feature scale influences gradient magnitude. With many parameters the scalar derivative becomes a vector. In a computational graph, the chain rule allows local derivatives to be multiplied in reverse order to obtain derivatives of the final objective with respect to early parameters.

Mastery lab

Write an analytic gradient and a finite-difference gradient for the same function. Compare them across several parameter values and tolerances. Investigate what happens when the finite-difference step is extremely small or large.

Mini-lab

Implement finite-difference numerical gradients and compare them with an analytically derived gradient.

06

Probability

Reason mathematically about uncertainty.

Core ideas

  • Sample spaces, events and conditional probability.
  • Random variables and probability distributions.
  • Expectation, variance and covariance.
  • Joint, marginal and conditional distributions.
  • Bayes' theorem and posterior reasoning.
  • Binomial, Bernoulli and Gaussian distributions.
Why it matters: Classification can be viewed as estimating a conditional probability such as P(y | x). Bayesian reasoning asks how evidence changes belief about a hypothesis.

First-principles lesson

Probability provides a formal language for uncertainty. Conditional probability P(A|B) asks how belief about A changes after observing B. Bayes' theorem follows directly from the definition of joint probability: P(A|B)=P(B|A)P(A)/P(B). The denominator normalizes the posterior so probabilities sum to one.

Random variables map outcomes to numerical values. A distribution describes how probability mass or density is assigned. Expectation is a probability-weighted average; variance measures dispersion around the mean; covariance measures how two variables move together. Independence is stronger than zero correlation and must not be treated as synonymous with it.

Worked example

Suppose a rare event has a 1% base rate and a detector has 95% sensitivity and 95% specificity. Bayes' theorem shows why a positive result does not automatically imply a 95% chance that the event is present. The base rate matters. This base-rate effect appears repeatedly in anomaly detection, medical prediction and classification.

Mastery lab

Construct a two-variable probability table and calculate marginal, joint and conditional probabilities. Verify every probability sum and then reproduce the posterior using Bayes' theorem.

Practice

Construct a small probability table, calculate conditional probabilities and verify Bayes' theorem numerically.

07

Statistics

Move from data description to inference.

Core ideas

  • Population versus sample.
  • Mean, median, variance, standard deviation and quantiles.
  • Covariance and correlation.
  • Sampling distributions and the central limit theorem intuition.
  • Point and interval estimation.
  • Hypothesis testing, p-values and practical significance.
  • Simple regression and statistical assumptions.
Important distinction: a confidence interval is an inferential procedure, not a guarantee that a fixed unknown parameter has a stated probability of lying inside one particular computed interval.

First-principles lesson

Statistics separates what is observed in a sample from what we want to say about a population. Descriptive statistics summarize observed data; inferential statistics quantify uncertainty when using a sample to learn about a broader process. Mean, median and quantiles answer different questions and can behave very differently under outliers.

Sampling distributions explain why estimates vary from sample to sample. The central limit theorem gives conditions under which normalized averages become approximately normal, which helps explain confidence intervals and many classical procedures. A p-value is a probability about data under a null model, not the probability that the null hypothesis is true.

AI/ML connection

Model evaluation is statistical measurement. A reported accuracy is an estimate from a finite sample. Confidence intervals, repeated validation and bootstrap methods can help quantify uncertainty. Statistical significance does not automatically imply operational importance; a tiny improvement can be statistically detectable while being economically irrelevant.

Mastery lab

Bootstrap a metric from a dataset, visualize its sampling distribution and report a confidence interval. Explain exactly what population, sample and estimand your calculation refers to.

Practice

Take a dataset, summarize it numerically and visually, estimate uncertainty, formulate a hypothesis and explain the result without confusing statistical and practical significance.

08

Optimization

Turn a learning objective into parameter updates.

Core ideas

  • Objective functions and feasible regions.
  • Gradient descent and learning rate.
  • Convex versus non-convex objectives.
  • Local minima, saddle points and convergence intuition.
  • Momentum and adaptive methods such as Adam.
  • Constrained optimization and Lagrange multiplier intuition.
w = 0.0 for _ in range(100): grad = 2*(w - 3) w -= 0.1*grad

First-principles lesson

Optimization asks for parameter values that minimize or maximize an objective subject to constraints. In ML, the objective usually measures disagreement between predictions and desired outcomes, possibly plus regularization. Convex problems have useful global structure; non-convex neural-network objectives can contain many stationary points and complicated geometry.

Gradient descent updates θ ← θ − η∇J(θ). The learning rate η controls the scale of movement. Momentum accumulates directional information, while adaptive optimizers rescale updates using statistics of past gradients. These methods change optimization dynamics, not the underlying definition of the learning problem.

Experiment design

Do not tune optimization by intuition alone. Record the objective curve, gradient magnitude, update magnitude and validation behavior. Separate optimization failure from generalization failure: a model can fit the training objective poorly because optimization is failing, or fit it extremely well while generalizing poorly.

Mastery lab

Optimize a quadratic function with several learning rates. Plot objective versus iteration, identify convergence and divergence, and write a short diagnosis for each run.

Mini-lab

Change the learning rate, plot the objective over iterations and identify slow convergence, overshooting and stable convergence.

09

AI vs ML vs deep learning

Understand the hierarchy before choosing techniques.

AI is the broad field of building systems that perform tasks associated with intelligent behavior. Machine learning is a family of approaches that learn patterns or decision rules from data. Deep learning uses multi-layer neural networks to learn representations and functions.

Decision rule

  • If a precise rule is stable and known, conventional software may be enough.
  • If the mapping is difficult to specify but examples exist, ML may be appropriate.
  • If representation learning from large/high-dimensional data is valuable, deep learning may be appropriate.

First-principles lesson

Artificial intelligence is the broad discipline; machine learning focuses on systems that improve behavior from data or experience; deep learning uses neural networks with multiple learned transformations. The categories overlap, but they answer different questions. The important engineering decision is not which label sounds advanced, but what information and structure the problem provides.

Supervised learning learns from input-output examples. Unsupervised learning discovers structure without a supplied target. Reinforcement learning learns from interaction and reward. Generative models learn distributions or conditional generation mechanisms. Rule-based systems remain appropriate when rules are explicit, stable and auditable.

Model-selection thought process

Start with the simplest system that can satisfy the requirement. Establish a baseline. Then introduce complexity only when experiments show that additional representation capacity, data, or modeling assumptions address a real limitation.

Mastery lab

For five problems, write the problem type, available supervision, expected output, baseline and reason a more complex model might or might not be justified.

Practice

Classify five real problems as rule-based software, supervised ML, unsupervised learning, reinforcement learning or generative AI and justify each choice.

Problem formulation

The model is downstream of the problem definition.

Ask these questions

  • What decision or prediction must be made?
  • At what exact time must it be made?
  • What information is available at that time?
  • What is the target and how is it measured?
  • What happens when the model is wrong?
  • What metric represents useful performance?
Example: “Predict churn” becomes a supervised classification problem only after defining the observation window, churn event, prediction horizon and eligible population.

First-principles lesson

Problem formulation converts a vague objective into an estimable quantity. A classification target requires a precise label definition. Forecasting requires a timestamp and horizon. Ranking requires an ordering objective. Generation requires a specification of acceptable outputs and evaluation criteria. Without this precision, model comparisons become meaningless.

Temporal availability is critical. Features must be available at prediction time. A feature generated after the outcome occurs may create excellent offline metrics while being impossible to use in production. The formulation should therefore include a timeline, not merely a feature list.

Decision-theoretic layer

A model prediction is usually not the final business action. Define the decision rule separately: who receives an intervention, what threshold is used, what cost is incurred and what happens when the prediction is wrong. This makes the relationship between model metrics and operational outcomes explicit.

Mastery lab

Write a formal specification for churn, fraud and demand forecasting. Include target construction, prediction timestamp, horizon, action, cost of errors and primary metric.

Deliverable

Write a one-page ML problem specification before touching a dataset or model.

11

Data & target design

A mathematically sophisticated model cannot rescue a broken dataset.

Core ideas

  • Features, labels and observations.
  • Missingness and measurement error.
  • Data leakage and temporal leakage.
  • Train, validation and test partitions.
  • Sampling bias and class imbalance.
  • Feature availability at prediction time.
Leakage test: ask “Could this feature exist in production at the exact moment the prediction is made?” If not, it cannot be a legitimate training feature.

First-principles lesson

The unit of observation is one of the most important hidden assumptions in a dataset. A row might represent a person, transaction, image, visit or time interval. Features describe information available for that observation; the target defines what the model is expected to predict. Mixing levels can create duplicated information and invalid evaluation.

Leakage occurs when information unavailable at prediction time enters training. Sampling bias occurs when the observed dataset differs systematically from the target population. Missingness can itself contain information, but blindly imputing values can hide measurement processes. Train, validation and test sets must be designed to reflect the way the system will encounter new data.

Mastery lab

Create a data contract describing schema, units, allowable ranges, missingness, provenance, target construction, split strategy and leakage checks. Treat the contract as part of the model specification.

Practice

Take a real dataset and document its unit of observation, target, feature availability, missingness, split strategy and leakage risks.

12

Training vs inference

Separate learning from using a learned system.

During training, parameters are adjusted using a training objective. During inference, the learned parameters are applied to new inputs. This distinction affects data pipelines, latency, cost, security and monitoring.

Core ideas

  • Parameters versus hyperparameters.
  • Training data versus unseen data.
  • Offline training versus online inference.
  • Batch versus real-time inference.
  • Distribution shift between training and production.

First-principles lesson

Training is an optimization process over historical data. Parameters change during training; inference should normally use fixed parameters for a given deployed model version. Hyperparameters such as learning rate or tree depth influence training but are not usually learned in the same inner optimization loop.

Production introduces a distribution shift problem. Input distributions can change, relationships between inputs and targets can change, or upstream pipelines can break. A model with excellent offline metrics can therefore degrade without any code change. Monitoring must observe both system behavior and data/model quality.

Systems view

Batch inference trades freshness for throughput and simplicity. Real-time inference prioritizes latency and availability. Training and inference may require different hardware, dependencies and scaling policies. Treat the boundary as an explicit interface with versioned artifacts.

Mastery lab

Design a training-to-inference architecture for a daily risk model and a sub-second recommendation API. Identify artifacts, schedules, monitoring signals and rollback points.

Practice

Draw a complete training-to-inference pipeline and identify where data enters, where parameters change and where monitoring belongs.

13

Loss functions

Define mathematically what “wrong” means to a learner.

Core ideas

  • Squared error for regression.
  • Absolute error and robustness intuition.
  • Log loss / cross-entropy for classification.
  • Probabilistic interpretation of likelihood.
  • Per-example loss versus aggregate objective.
  • Regularization as part of an optimization objective.
Key distinction: the loss used to train a model and the metric used to judge whether it is useful need not be identical. The choice must reflect the learning problem and operational objective.

First-principles lesson

A loss function maps an error into a numerical quantity that optimization can minimize. Mean squared error strongly penalizes large residuals. Absolute error is less sensitive to extreme residuals. Binary cross-entropy measures the mismatch between a binary outcome and a predicted probability and has a direct likelihood interpretation under a Bernoulli model.

The training objective is often an empirical average: J(θ)=1/n Σᵢ L(f(xᵢ;θ),yᵢ). Regularization adds a preference for certain parameter configurations. The loss therefore encodes both data fit and, sometimes, assumptions about model complexity.

Numerical behavior

Probabilities near zero or one can create logarithmic numerical issues. Stable implementations use transformations such as logits and log-sum-exp rather than naïvely evaluating exponentials and logarithms. Numerical stability is part of correctness, not an optimization afterthought.

Mastery lab

Implement MSE, MAE and binary cross-entropy from scratch. Compare their response to outliers and extreme probabilities, then test your implementation against a trusted library.

Mini-lab

Implement MSE and binary cross-entropy with NumPy, inspect their values for correct and incorrect predictions, and explain their behavior.

14

Model evaluation

Measure generalization, not memorization.

Core ideas

  • Train/validation/test methodology.
  • Accuracy, precision, recall and F1.
  • Confusion matrices and threshold selection.
  • ROC-AUC and precision-recall curves.
  • Regression metrics such as MAE, MSE and RMSE.
  • Calibration and uncertainty.
  • Cross-validation and model selection.
Metric choice: in a rare-event problem, accuracy can remain high while the model misses most positive cases. Evaluation must therefore be tied to the actual decision costs and data distribution.

First-principles lesson

Evaluation is an estimation problem. Accuracy, precision, recall, F1, ROC-AUC, PR-AUC, calibration, MAE and RMSE answer different questions. The correct metric depends on the decision context and error costs. A single metric can conceal severe failure modes in subgroups or rare-event settings.

Validation data supports model selection; the test set should provide an approximately unbiased final estimate after choices are frozen. Repeated experimentation against the test set turns it into a de facto validation set and weakens the credibility of the reported result.

Worked analysis

For an imbalanced classifier, 99% accuracy can be achieved by always predicting the majority class. A confusion matrix exposes this failure. Precision asks how many predicted positives are correct; recall asks how many actual positives were recovered. Threshold selection then becomes a decision problem rather than a default of 0.5.

Mastery lab

Evaluate one classifier at multiple thresholds. Produce a confusion matrix, precision-recall curve and calibration view. Write which metric should drive deployment and why.

Practice

Evaluate one classifier using a confusion matrix plus at least three appropriate metrics, then explain which metric should drive the operational decision and why.

15

Bias–variance

Understand why a model can fail by being too simple or too sensitive.

Bias captures systematic error from restrictive assumptions; variance captures sensitivity to the particular training sample. Generalization depends on controlling both rather than maximizing training fit.

Diagnose with evidence

  • High training error and high validation error can indicate underfitting.
  • Very low training error with substantially higher validation error can indicate overfitting.
  • Learning curves help separate data limitations from model limitations.

First-principles lesson

Bias-variance is a useful framework for understanding generalization error. A model with insufficient capacity can systematically miss structure, while a highly flexible model can fit idiosyncrasies of the training sample. The observed error is also affected by irreducible noise, so not every error can be removed by choosing a larger model.

Learning curves reveal whether additional data or model capacity is likely to help. If both training and validation errors are high, the model may be underfitting. If training error is low but validation error is much higher, variance or distribution mismatch may be involved.

Experimental reasoning

Do not use bias and variance as labels without evidence. Compare training and validation curves, change capacity systematically and control other variables. This turns a conceptual framework into an empirical diagnosis.

Mastery lab

Train models of increasing capacity on the same dataset. Plot training and validation error and write a diagnosis for each regime.

Practice

Train models of increasing complexity and plot training and validation error. Explain the region where additional complexity stops improving generalization.

16

Overfitting & regularization

Control complexity and improve generalization.

Core ideas

  • L1 and L2 penalties.
  • Early stopping.
  • Dropout.
  • Data augmentation.
  • Cross-validation.
  • Feature selection and dimensionality reduction.
  • More data and better data as alternatives to merely increasing regularization.
Important principle: regularization is not a magic switch. It changes the optimization problem so that certain parameter configurations become less attractive. The right amount must be established empirically on validation data.

First-principles lesson

Regularization changes the learning problem by discouraging solutions that fit training data in undesirable ways. L2 regularization penalizes large parameter magnitudes; L1 encourages sparsity in many settings. Early stopping limits optimization before the model fully adapts to the training data. Dropout injects stochastic perturbation during training, while data augmentation changes the effective training distribution.

Cross-validation estimates how a method behaves across multiple training/validation partitions. It is particularly useful when data is limited, but it must respect temporal or grouped structure when ordinary random splitting would leak information across folds.

Under the hood

Regularization is not magic. It introduces a trade-off between fitting observed data and imposing a preference over solutions. The strength of the penalty is a hyperparameter and must be selected without contaminating the final test evaluation.

Mastery lab

Compare an unregularized model with L1, L2 and early stopping. Track training loss, validation loss, parameter magnitude and final test performance.

Mini-lab

Fit an over-parameterized model, then compare no regularization, L2 regularization and early stopping using identical validation data.

17

Ethics & responsible AI

Technical capability must be accompanied by responsible deployment.

Core ideas

  • Fairness and disparate impact.
  • Privacy and data minimization.
  • Transparency and documentation.
  • Safety, robustness and abuse resistance.
  • Human oversight and accountability.
  • Security and access control.
  • Auditability and incident response.
Engineering question: “Can the model make this prediction?” is different from “Should the organization use this prediction for this decision?” Both questions belong in the system design process.

First-principles lesson

Responsible AI is an engineering discipline, not a final paragraph added after deployment. Systems can create privacy, security, fairness, safety and accountability risks through their data, objective, interface or operating environment. Risk analysis should begin during problem formulation and continue through deployment.

Fairness is not one universal metric. Different definitions can conflict under realistic conditions, so teams must state the population, protected attributes where legally and ethically appropriate, metric and decision context. Privacy requires minimizing unnecessary collection and controlling access. Safety requires identifying harmful outputs or actions and designing mitigations.

Governance workflow

Document intended use, prohibited use, data provenance, known limitations, evaluation results, human oversight and incident procedures. For generative systems, add prompt-injection testing, data exfiltration tests and output validation. For high-impact decisions, define escalation paths rather than assuming model confidence is equivalent to correctness.

Mastery lab

Perform a lightweight risk assessment for an AI assistant. Produce a threat model, data-flow diagram, failure-mode register, evaluation plan and human-oversight policy.

Before completing Stage 00

Write a short risk assessment for an ML system covering affected people, data risks, failure modes, fairness concerns, security threats, human oversight and monitoring.

  • Implement a small numerical optimization algorithm from scratch.
  • Explain the linear-algebra shapes and operations in your implementation.
  • Perform a statistical analysis on a dataset and state uncertainty appropriately.
  • Formulate an ML problem with a defensible target, split and metric.
