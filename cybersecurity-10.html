01 · Mission of malware analysis

Malware analysis turns suspicious software into evidence about identity, capabilities, execution, infrastructure and defensive action.

Analyst questions

  • What is the artifact?
  • What does it do?
  • When and why does behavior occur?
  • What systems and data can it affect?
  • How can defenders detect and contain it?
Rule: distinguish observed behavior from inference and hypothesis.

02 · Safe research environments

Unknown malware belongs in an isolated, disposable analysis environment. Use snapshots, controlled networking and no production credentials, shared folders or personal data.

  • Isolate the host and network.
  • Preserve original samples and hashes.
  • Record acquisition and execution conditions.
  • Use simulated services where possible.
Authorized research only: never execute unknown malware on ordinary personal or enterprise systems.

03 · Sample triage and identity

Start with SHA-256, file type, architecture, size, timestamps, signer information and provenance. Hashes identify exact artifacts but do not establish family relationships.

Useful clues

  • PE/ELF/script/document format
  • 32/64-bit architecture
  • Authenticode status
  • Sections and entropy
  • Imports, exports and resources

04 · PE executable anatomy

The Windows Portable Executable format describes how an executable image is laid out and loaded. Important structures include headers, sections, entry point, imports, exports, relocations and resources.

file → loader → mapped image → imports/relocations → entry point

Unusual section permissions, embedded data or unexpected loader characteristics can become analytical clues.

05 · CPU architecture and assembly

Reverse engineering reconstructs higher-level behavior from machine instructions, registers, memory, branches and calls.

Core skills

  • Instruction pointer and registers
  • Stack frames and calling conventions
  • Conditional branches
  • Indirect calls/jumps
  • Data and control flow

Read code as a graph of behavior, not as isolated instructions.

06 · Static analysis

Static analysis examines an artifact without execution. Strings, imports, exports, resources, control-flow graphs and configuration structures provide clues.

Static evidence can be incomplete when code is packed, encrypted, dynamically resolved or conditionally executed. An API reference alone does not prove that the capability ran.

07 · Dynamic analysis and telemetry

Dynamic analysis observes runtime behavior in a controlled environment: process creation, modules, files, registry, network, memory and persistence.

Microsoft Sysmon provides detailed Windows telemetry including process creation, hashes, network connections and file timestamp changes. citeturn0search0turn0search4

process tree + timeline + host state + network state = behavioral model

08 · Windows processes, DLLs and memory

Understand processes, threads, DLL loading, handles, virtual memory and access permissions. Malware often abuses legitimate operating-system facilities, so context matters more than a simple list of APIs.

A signed Windows component can still be used maliciously; investigate who launched it, from where, with which arguments and what happened afterward.

09 · Packing and obfuscation

Packing compresses or encrypts code/data so useful content appears only at runtime. Obfuscation changes representation to hinder analysis.

  • High or unusual entropy
  • Few imports despite complex behavior
  • Runtime executable memory
  • Small initial code surface

MITRE ATT&CK tracks obfuscation and software packing as defense-evasion behaviors.

10 · Anti-analysis behavior

Samples may detect debuggers, virtualization, instrumentation, timing anomalies or analysis artifacts.

“Nothing happened” is not proof of benign behavior. Record environmental conditions and compare static capabilities with runtime results.

  • Environment checks
  • Timing-dependent behavior
  • Debugger detection
  • Delayed execution

11 · Memory forensics

Runtime memory can contain unpacked code, decrypted strings, configuration, injected code and volatile network state.

Memory acquisition must preserve the original capture, hash it and document the acquisition method. Interpretation depends on operating-system version and capture quality.

12 · Network behavior

Observe DNS, destination addresses, ports, TLS metadata, application protocols, timing and the process responsible for each connection.

Encrypted traffic may hide content and a suspicious destination does not prove maliciousness. Correlate network evidence with host evidence.

13 · Scripts, fileless execution and AMSI

Threats can execute through PowerShell, JavaScript, VBScript and other runtime environments without a conventional executable. Microsoft AMSI provides an inspection interface for script and other dynamic content. citeturn0search1turn0search5

Trace content from source through decoding/deobfuscation to the execution engine, then correlate it with process and network telemetry.

14 · Persistence and system modification

Analyze startup/logon mechanisms, scheduled execution, services, drivers, registry-backed configuration and application extension points.

For every persistence finding ask: what changed, who changed it, when, on which host, and is the change legitimate?

15 · Configuration and capability mapping

Malware configuration may contain infrastructure, campaign identifiers, feature flags or cryptographic parameters. It can be embedded or generated at runtime.

Map capabilities to execution, persistence, discovery, credential access, collection, command-and-control and impact. Keep mappings evidence-based.

16 · From reverse engineering to detection

Translate findings into hashes and certificates, process relationships, persistence changes, network indicators and behavior-based detections.

Sysmon can provide host telemetry while AMSI adds visibility into dynamic script content. These are complementary layers, not complete detection systems. citeturn0search3turn0search6

17 · Professional malware reports

A defensible report contains sample identity, acquisition context, executive summary, static findings, dynamic findings, configuration, network behavior, indicators, detection opportunities, limitations and response recommendations.

Use confidence language: observed, strongly inferred and hypothesized are different evidentiary states.

18 · Advanced reverse-engineering workflow

triage → static model → controlled execution → telemetry → memory/code correlation → capability map → detection → report

Advanced analysis is iterative. Build a hypothesis, test it, correlate evidence, revise the model and document uncertainty.

Mastery: the goal is not merely to identify what malware does, but to explain why the evidence supports the conclusion and how defenders can act on it.

Mastery review · 20 questions with answers

01 · What is malware analysis?
Answer: The evidence-driven study of suspicious software to determine identity, capabilities, behavior, infrastructure and defensive implications.
02 · Why hash a sample?
Answer: A cryptographic hash identifies an exact artifact; it does not describe its behavior or prove family relationships.
03 · What is static analysis?
Answer: Analysis of an artifact without executing it, using structures such as strings, imports, resources and control flow.
04 · What is dynamic analysis?
Answer: Observation of a sample executing in a controlled environment to reveal runtime behavior.
05 · What is the PE format?
Answer: The Windows Portable Executable format describing executable image structure and loading information.
06 · Why are imports useful?
Answer: They provide clues about libraries and APIs a program may use, but an import alone does not prove execution.
07 · What is packing?
Answer: A transformation that hides or compresses executable content until runtime.
08 · Why can strings mislead?
Answer: Strings can be dead data, decoys, encoded data or unreachable references.
09 · Why analyze memory?
Answer: Runtime memory can contain unpacked code, decrypted configuration and volatile artifacts absent from the file.
10 · What is anti-analysis?
Answer: Behavior designed to detect or interfere with debugging, virtualization, instrumentation or analysis environments.
11 · Why correlate process trees?
Answer: Parent-child relationships provide context for how execution progressed.
12 · What is AMSI?
Answer: A Windows interface allowing applications and security products to inspect content such as scripts and dynamically generated code.
13 · What is a behavioral indicator?
Answer: A repeatable observable action or relationship, such as a suspicious process sequence or persistence change.
14 · Why analyze network behavior?
Answer: It can reveal infrastructure, protocols, retrieval and command-and-control patterns.
15 · What is malware configuration?
Answer: Data controlling features, infrastructure, identifiers or other runtime behavior.
16 · Why use ATT&CK?
Answer: It provides a common behavioral vocabulary for mapping observed techniques to defensive coverage.
17 · What makes a report defensible?
Answer: Clear evidence, reproducible observations, explicit uncertainty and separation of observation from inference.
18 · Why is isolation essential?
Answer: Unknown malware can modify systems, communicate externally or expose credentials and data.
19 · What is the advanced workflow?
Answer: Iteratively form hypotheses, gather static/runtime evidence, correlate it, revise conclusions and translate findings into detections.
20 · What is the ultimate goal?
Answer: Reliable understanding that improves detection, containment, eradication and recovery.
