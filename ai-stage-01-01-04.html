Integers, floating point & numerical representation

Understand exact integers, approximate real numbers and numerical failure modes.

FIRST PRINCIPLESWORKED EXAMPLEIMPLEMENTATIONMASTERY GATE

1. Why this matters

Integers can be represented exactly within a supported range. Floating point approximates a much larger mathematical set using finite bits for sign, exponent and significand.

2. Formal model

A useful model is x = sign × significand × base^exponent. Many decimal fractions have no finite binary representation, so storage requires rounding.

3. Worked example

The familiar 0.1 + 0.2 example demonstrates that displayed decimal notation does not imply exact binary storage.

4. Implementation

The implementation is intentionally small so the underlying concept remains visible.

a = 0.1
b = 0.2
print(a + b == 0.3)
print(a + b)

5. Execution trace

The comparison can be false because the stored approximations of 0.1, 0.2 and 0.3 are not related by exact real-number arithmetic.

6. Under the hood

CPython floats are generally C double precision. Hardware operations produce rounded results. Underflow, overflow, cancellation and accumulation error can matter.

7. Complexity / engineering implications

Numerical stability affects softmax, logarithms, gradient calculations and losses. Stable formulations preserve mathematical intent while reducing avoidable error.

8. Failure modes & misconceptions

Do not use == casually for approximate floating-point results. More displayed digits do not imply more mathematical accuracy.

9. Engineering lab

Compare direct and max-shifted softmax on large-magnitude inputs. Document the numerical failure mechanism.

10. Mastery gate

Explain precision versus range, rounding error, overflow, underflow and cancellation, and identify when approximate equality is appropriate.
