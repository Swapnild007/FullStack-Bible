The mental model

React is a way to describe an interface as a tree of components.

React's current documentation describes components as pieces of UI with their own logic and appearance. A component is commonly a JavaScript function that returns JSX. React then updates the rendered interface when the data that drives it changes. React Quick Start.

Component

A reusable piece of UI with a defined job. It can be as small as a button or as large as a page section.

Props

Inputs passed from a parent to a child. They let the same component display different data or behaviour.

State

Information a component needs to remember between interactions, such as a selected tab or input value.

Events

User actions such as clicks, typing and submitting forms can trigger state updates and therefore new UI.

Core idea: describe what the UI should look like for the current data. Do not build your React app by manually finding DOM nodes and changing them one by one.
01 · React

Understand what React adds.

React is not a replacement for JavaScript

React is a JavaScript library for user interfaces. You still use JavaScript or TypeScript, functions, arrays, objects, conditions and modules. React adds a component model and a way to describe UI with JSX.

That is why the earlier modules matter: React becomes much easier when you already understand functions, objects, arrays, events, browser behaviour and TypeScript.

JSX: markup inside your component logic

JSX lets you write HTML-like markup in JavaScript or TypeScript. It is not HTML copied into a string. It is syntax that React tooling transforms into JavaScript expressions.

function Greeting() {
  const name = "Swapnil";

  return (
    <section>
      <h1>Hello, {name}</h1>
      <p>Welcome to React.</p>
    </section>
  );
}

Curly braces let you insert JavaScript expressions into JSX. Keep the returned UI readable; extract a component when a section develops its own meaningful responsibility.

Rendering lists and conditions

React uses normal JavaScript for conditions and commonly uses map() to turn data into lists. Each rendered list item needs a stable key that identifies the item among its siblings.

const lessons = [
  { id: 1, title: "React basics", done: true },
  { id: 2, title: "State", done: false }
];

function LessonList() {
  return (
    <ul>
      {lessons.map(lesson => (
        <li key={lesson.id}>
          {lesson.title} {lesson.done ? "✓" : ""}
        </li>
      ))}
    </ul>
  );
}

Do not use array indexes as keys when the list can be reordered, inserted into or deleted from. Prefer an identifier belonging to the data.

02 · Components

Build UI from small, understandable pieces.

Your first component

A function component receives inputs and returns UI. Component names begin with a capital letter so JSX can distinguish your component from built-in HTML elements.

type BadgeProps = {
  label: string;
  tone: "blue" | "green" | "gray";
};

function Badge({ label, tone }: BadgeProps) {
  return <span data-tone={tone}>{label}</span>;
}

Because this module follows TypeScript, props should be typed deliberately. React's official TypeScript guide recommends describing component props with object types such as a type or interface. React: Using TypeScript.

Component boundaries

A good component boundary usually appears when a piece of UI has its own responsibility, repeated structure, data contract, state, or interaction. Do not split every div into a component. The goal is understandable composition, not maximum file count.

Too small

One component for a single decorative wrapper can make the code harder to follow.

Too large

A 500-line component mixing data, forms, navigation and every visual detail is difficult to change safely.

Component tree

Think about the UI as a tree. A page may contain an app shell, navigation, dashboard, cards, buttons and list items. Data should flow through this tree in understandable directions.

App
├─ Header
├─ Sidebar
└─ Dashboard
   ├─ ProgressCard
   ├─ LessonList
   │  └─ LessonItem
   └─ EmptyState
03 · Props & composition

Make components configurable without making them confusing.

Props are inputs

Props let a parent provide information to a child. Treat props as read-only inputs: the child should not mutate them. If something needs to change, the parent can own the state and pass an event handler down.

type LessonCardProps = {
  title: string;
  completed: boolean;
  onOpen: () => void;
};

function LessonCard({ title, completed, onOpen }: LessonCardProps) {
  return (
    <article>
      <h3>{title}</h3>
      <p>{completed ? "Completed" : "Not completed"}</p>
      <button onClick={onOpen}>Open</button>
    </article>
  );
}

Children and composition

Some components are useful because they provide a visual or behavioural container around arbitrary content. The children prop allows a parent to place JSX inside that component.

type CardProps = {
  title: string;
  children: React.ReactNode;
};

function Card({ title, children }: CardProps) {
  return (
    <section className="card">
      <h2>{title}</h2>
      {children}
    </section>
  );
}

Composition is often clearer than creating dozens of special-purpose variants. React's TypeScript documentation identifies React.ReactNode as a common type for children.

Keep rendering predictable

React's model works best when components behave like predictable functions of their inputs. Avoid hidden mutations during rendering. Calculate what you need, return the UI, and perform external side effects only through the appropriate React mechanisms.

04 · State & events

Interactivity comes from state changing over time.

State is remembered information

Use useState when a component needs to remember information that can change because of interaction. Updating state asks React to render again using the new value.

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}

React's documentation notes that state updates do not immediately change the current render's value. Think of each render as a snapshot of the UI at that moment.

Events

Event handlers are functions you pass to JSX props such as onClick, onChange and onSubmit. React calls the handler when the interaction occurs.

function SaveButton() {
  function handleClick() {
    console.log("Saving...");
  }

  return <button onClick={handleClick}>Save</button>;
}

Do not write onClick={handleClick()} when you mean “run this after the click”; that calls the function while rendering instead of passing the handler.

Updating objects and arrays

Do not mutate objects or arrays stored in state. Create a new value that represents the update.

setProfile(current => ({
  ...current,
  displayName: "Swapnil"
}));

setLessons(current =>
  current.map(lesson =>
    lesson.id === id
      ? { ...lesson, completed: true }
      : lesson
  )
);

This makes changes explicit and gives React a new value to work with.

Controlled inputs

A controlled input gets its current value from React state and reports user changes through an event handler. This is especially useful for forms, validation, filtering and search.

const [query, setQuery] = useState("");

return (
  <input
    value={query}
    onChange={event => setQuery(event.target.value)}
    placeholder="Search lessons"
  />
);

Lifting state up

When two components need to stay in sync, move their shared state to their closest common parent and pass the current value and event handlers down as props. React calls this lifting state up. It creates a clear owner for that piece of state. React: Sharing State Between Components.

function Accordion() {
  const [activeId, setActiveId] = useState<number | null>(null);

  return (
    <>
      <Panel
        active={activeId === 1}
        onShow={() => setActiveId(1)}
      />
      <Panel
        active={activeId === 2}
        onShow={() => setActiveId(2)}
      />
    </>
  );
}
05 · Reusable UI

Reuse behaviour, not just markup.

Design a component API

A reusable component needs a small, understandable contract. Ask: what data must the parent provide? What actions can the user take? Which visual choices are intentional variants? What should the component own internally?

Good contract

Button accepts a label/children, disabled state, variant and click handler.

Hidden coupling

Button secretly reads global variables, changes unrelated state and assumes a particular page.

Variants with union types

TypeScript can make reusable component APIs explicit. Literal unions prevent callers from inventing arbitrary variant names.

type ButtonProps = {
  variant: "primary" | "secondary" | "danger";
  disabled?: boolean;
  children: React.ReactNode;
  onClick: () => void;
};

Derived data should usually stay derived

Do not create state for information you can calculate from existing state. If completedCount is always the number of completed lessons, calculate it from lessons rather than maintaining two values that can drift apart.

const completedCount = lessons.filter(
  lesson => lesson.completed
).length;

React's state-management guidance specifically warns that redundant or duplicate state is a common source of bugs. React: Managing State.

Accessibility remains part of reusable UI

A reusable component is not truly reusable if every consumer must repair its accessibility. Prefer native HTML elements where possible, preserve keyboard behaviour, label controls, expose meaningful names and keep focus behaviour understandable. React does not remove the accessibility responsibilities you learned in Module 02.

Capstone lab

Build a React learning dashboard.

Convert the ideas from Module 03 and the type-safe data model from Module 05 into a component-driven interface. The goal is not a giant app. The goal is learning how to design a clean React component tree and data flow.

Project structure

react-learning-dashboard/
├─ src/
│  ├─ components/
│  │  ├─ Header.tsx
│  │  ├─ ProgressCard.tsx
│  │  ├─ LessonList.tsx
│  │  ├─ LessonCard.tsx
│  │  ├─ SearchInput.tsx

│  ├─ App.tsx
│  └─ main.tsx
└─ package.json

Build requirements

  1. Create typed lesson data with stable IDs.
  2. Render lessons through a reusable LessonCard.
  3. Add search using controlled state.
  4. Add a completed/uncompleted interaction.
  5. Show empty, populated and filtered states.
  6. Calculate progress from lesson data instead of duplicating it in state.
  7. Lift state to the appropriate common parent.
  8. Create reusable Button, Card and Badge components with typed props.
  9. Use keyboard-accessible native controls.
  10. Use React DevTools and browser DevTools to inspect and debug the app.

Architecture challenge

Before coding, draw your component tree. Then mark which component owns each piece of state. If a child needs to change parent-owned state, pass an event handler down. If several siblings need the same state, move ownership to their closest useful common parent.

Completion test: You should be able to explain why every state value lives where it does, what each component receives through props, and what causes each visible UI change.
Do not add a state-management library yet. First learn React's built-in data flow, state and composition model. More advanced state tools make much more sense after you understand what problem they are solving.
