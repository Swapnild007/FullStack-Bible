The mental model

HTML gives the page structure. CSS gives it appearance. JavaScript gives it behaviour.

JavaScript is a programming language. In a browser, it can use browser-provided objects and APIs to respond to user actions, change the page, store data and communicate with servers. The language itself and the browser environment are related but not the same thing. MDN separates the JavaScript language from the browser APIs built around it. MDN: What is JavaScript?

Language

Variables, values, functions, objects, arrays, conditions, loops, errors, modules and the rules of JavaScript itself.

Page

The DOM is the browser's in-memory representation of the document. JavaScript can read it, change it, add things and remove things.

Browser

The browser supplies APIs for things outside the core language: storage, timers, URLs, history, network requests, media and more.

Network

Asynchronous APIs let your page request data without freezing while the network operation is still in progress.

Rule for this module: do not learn JavaScript by memorising snippets. Learn what a value is, what a function receives and returns, what the browser is doing, and what evidence you can inspect when something fails.
01 · JavaScript in depth

Move from syntax to real programming.

Module 02 introduced the basic language. Here you use those pieces together and develop habits that will still matter when you later use TypeScript, React or a server runtime. MDN's JavaScript Guide covers grammar and types, control flow, functions, objects, promises and modules as core parts of the language. MDN JavaScript Guide.

Values and variables

A variable gives a value a name so your program can use it again. Prefer const when the variable binding does not need to be reassigned; use let when it does. Avoid var in new beginner code because its older scoping rules make programs harder to reason about.

const learner = "Swapnil";
let lessonsCompleted = 0;

lessonsCompleted = lessonsCompleted + 1;

The important distinction is between the name and the value. learner is a binding whose current value is the string "Swapnil".

Strings, numbers, booleans and null

JavaScript has different kinds of values. Strings represent text, numbers represent numeric values, booleans represent true or false, and null is commonly used to represent an intentional absence of a value. JavaScript also has undefined, which often appears when a value has not been provided.

Do not rely on automatic conversion without understanding it. For example, user input from an HTML text field is normally a string even when the user typed digits. Convert it deliberately when your program needs a number.

const text = "42";
const number = Number(text);

console.log(typeof text);   // "string"
console.log(typeof number); // "number"

Comparison and conditions

Your program constantly needs to make decisions. Use comparisons to produce true/false results, then use if, else if and else to choose what happens.

const score = 82;

if (score >= 90) {
  console.log("Excellent");
} else if (score >= 60) {
  console.log("Keep going");
} else {
  console.log("Review the lesson");
}

Prefer strict equality, ===, when you mean “same value and same type”. Its opposite is !==.

Functions: turn an idea into a reusable operation

A function packages a task. It can receive input through parameters and can send a result back with return. A function should ideally have a clear responsibility.

function calculateProgress(done, total) {
  if (total === 0) return 0;
  return Math.round((done / total) * 100);
}

const progress = calculateProgress(7, 10);
console.log(progress); // 70

Separate “calculate something” from “change the page”. This makes code easier to test and reuse.

Arrays: work with collections

An array stores an ordered collection. Learn the common operations rather than treating arrays as numbered boxes.

const topics = ["HTML", "CSS", "JavaScript"];

topics.push("Accessibility");

const longNames = topics.map(topic => topic.toUpperCase());
const webTopics = topics.filter(topic => topic !== "Accessibility");

console.log(topics.length);

map() creates a new array from transformed values. filter() creates a new array containing values that pass a test. These patterns become extremely important when you work with data from APIs.

Objects: keep related information together

An object groups named properties. It is one of the most common shapes you will see in JavaScript applications and JSON data.

const learner = {
  name: "Swapnil",
  module: 3,
  completed: true
};

console.log(learner.name);
console.log(learner["module"]);

Objects can contain arrays, other objects and functions. Learn to read nested data without fear.

Scope: know where a name exists

Scope determines where a variable can be accessed. A variable declared inside a block with let or const is normally available only inside that block. Function parameters and local variables are also scoped to their function.

const outside = "available here";

if (true) {
  const inside = "only inside this block";
  console.log(outside);
  console.log(inside);
}

console.log(outside);
// console.log(inside); // ReferenceError

When debugging, ask: “Does this variable exist here?” before assuming the value itself is wrong.

Errors are information

JavaScript can report syntax errors, reference errors, type errors and other failures. Read the error message, identify the file and line, reproduce the problem, and inspect the values involved.

try {
  const result = JSON.parse("not valid JSON");
  console.log(result);
} catch (error) {
  console.error("Could not parse the data:", error);
}

Do not hide every error with try...catch. Catch an error when you can actually handle it or provide a useful recovery path.

Do not jump ahead: classes, advanced metaprogramming and obscure language tricks are not required to make useful web applications. First become excellent at values, functions, objects, arrays, control flow, errors and composition.
02 · DOM & browser interaction

Control the page you built.

The DOM connects web documents to scripts. The browser represents the document as a tree of objects, and JavaScript can find nodes, change their content and attributes, create new nodes, remove nodes and respond to events. MDN: DOM scripting · WHATWG DOM Standard.

Finding elements

Use selectors that describe what you mean. querySelector() returns the first matching element. querySelectorAll() returns a collection of all matches.

const title = document.querySelector("h1");
const buttons = document.querySelectorAll("button");

console.log(title.textContent);
console.log(buttons.length);

Prefer meaningful classes or attributes when you control the HTML. Avoid selectors that depend on fragile visual details.

Changing content and attributes

textContent is useful for plain text. Attributes can be read and changed with methods such as getAttribute() and setAttribute(). Use the DOM API instead of building HTML strings when plain text is all you need.

const message = document.querySelector("#message");
message.textContent = "Saved successfully";

const image = document.querySelector("img");
image.setAttribute("alt", "A learner working on a laptop");
Security habit: never put untrusted user input into innerHTML just because it is convenient. Treat data as data. Use textContent when you want text.

Classes are usually better than manual style changes

JavaScript should normally describe a state, while CSS describes how that state looks.

const panel = document.querySelector(".panel");
panel.classList.toggle("is-open");

Then CSS controls .is-open. This keeps behaviour and presentation easier to maintain.

Creating and removing elements

const list = document.querySelector("ul");
const item = document.createElement("li");
item.textContent = "Async JavaScript";
list.append(item);

// Later:
item.remove();

This is the foundation for dynamic lists, notifications, menus, search results and application screens.

Events: make interaction happen

An event is a signal that something happened. A user clicked, typed, submitted a form, resized the window, or a resource finished loading. Use addEventListener() to react to events. MDN: Introduction to events.

const button = document.querySelector("button");

button.addEventListener("click", (event) => {
  console.log("Clicked", event.currentTarget);
});

The event object contains information about what happened. event.target is the object where the event originated; event.currentTarget is the element whose listener is currently running.

Preventing default browser actions

Some browser actions have a default behaviour. A form normally submits. A link normally navigates. You can call event.preventDefault() when your application intentionally needs to handle the interaction itself.

form.addEventListener("submit", (event) => {
  event.preventDefault();
  // validate and process the form here
});

Do not prevent defaults automatically. Native browser behaviour is often useful and accessible.

Event bubbling and delegation

Events can travel from a deeply nested element toward its ancestors. This is called bubbling. It enables event delegation: one listener on a parent can handle interactions from many child elements. MDN: Event bubbling.

const list = document.querySelector(".tasks");

list.addEventListener("click", (event) => {
  const button = event.target.closest("button[data-delete]");
  if (!button) return;

  button.closest("li")?.remove();
});

This pattern becomes valuable when your list changes after the page loads.

03 · Browser APIs

Use what the browser already provides.

A browser API is a set of features exposed by the browser environment. These are not all part of the JavaScript language itself. MDN groups APIs for areas such as storage, networking, media and other browser capabilities. MDN: Introduction to Web APIs.

Window

Represents the browser window or tab environment. It gives access to things such as the current location, timers and viewport information.

Document

Represents the loaded page. This is where your DOM work happens.

Navigator

Provides information about the browser environment and access to some browser capabilities.

Storage

localStorage and sessionStorage can store simple string values in the browser. They are not a database replacement.

Timers

setTimeout() schedules a function to run later. setInterval() schedules repeated execution until it is stopped. Timing is not the same thing as guaranteeing exact execution time; the browser decides when queued work can run.

const timer = setTimeout(() => {
  console.log("This happened later");
}, 1000);

const interval = setInterval(() => {
  console.log("Tick");
}, 1000);

clearInterval(interval);

Remembering simple data

Web Storage provides localStorage and sessionStorage. Local storage persists across browser sessions for the same origin; session storage is associated with a page session. Both store strings and are synchronous, so they are useful for small pieces of simple state, not large application databases. MDN: Web Storage API.

const settings = { theme: "light", compact: true };
localStorage.setItem("settings", JSON.stringify(settings));

const saved = localStorage.getItem("settings");
const restored = saved ? JSON.parse(saved) : null;

URL and location

The browser exposes information about the current address through location and provides the URL interface for reading and constructing URLs. Learn to work with URLs as structured data rather than manually cutting strings apart.

const current = new URL(window.location.href);
console.log(current.pathname);
console.log(current.searchParams.get("lesson"));

Browser APIs are not magic

When you meet an unfamiliar API, ask four questions: What problem does it solve? What object or function do I call? What does it return? What can fail? Then read the official documentation and test a tiny example before putting it into a larger application.

04 · Forms

Take real input from real people.

Forms are one of the most important bridges between a person and an application. HTML provides the native controls and browser validation; JavaScript lets you add application-specific behaviour. MDN's forms material treats forms as a core way to collect user data and control interfaces.

Start with HTML, not JavaScript

Use the correct native control for the information you need. A text input is not automatically better than a number input, checkbox, radio group or select. Native controls give browsers and assistive technologies information they can understand.

<form id="profile-form">
  <label for="name">Name</label>
  <input id="name" name="name" autocomplete="name" required>

  <label for="age">Age</label>
  <input id="age" name="age" type="number" min="1" max="120" required>

  <button type="submit">Save</button>
</form>

Read form values

Input elements expose their current value through value. A checkbox uses checked. Always remember that text input values are strings until you intentionally convert them.

const form = document.querySelector("#profile-form");
const name = form.elements.name.value.trim();
const age = Number(form.elements.age.value);

Validate before doing work

The browser can perform basic constraint validation when you use attributes such as required, min, max, type="email" and patterns. JavaScript can check additional rules your application needs.

form.addEventListener("submit", (event) => {
  event.preventDefault();

  if (!form.checkValidity()) {
    form.reportValidity();
    return;
  }

  const data = new FormData(form);
  console.log(Object.fromEntries(data));
});

Client-side validation improves the experience, but it is not a security boundary. When data reaches a server, the server must validate it again.

FormData: collect the form as data

FormData represents the fields and values from a form. It becomes especially useful when you later send data to a server.

const data = new FormData(form);

for (const [name, value] of data.entries()) {
  console.log(name, value);
}

Good form behaviour

  • Every important field has a visible label.
  • Use the correct input type and native controls.
  • Keep error messages close to the field they describe.
  • Do not erase user input just because validation failed.
  • Keep the submit button understandable.
  • Do not disable controls unnecessarily.
  • Show what happened after submission: success, validation problem or network failure.
Think in three layers: HTML handles the basic structure and native behaviour. JavaScript handles interaction and application rules. The server, later in the curriculum, becomes the final authority for data that matters.
05 · Asynchronous JavaScript

Keep the page alive while work is happening.

A network request can take time. If your program stopped responding until every request finished, modern web applications would feel broken. Asynchronous JavaScript lets work continue while your program remains able to respond to other events. MDN covers callbacks, promises, async/await and network requests in its asynchronous JavaScript material. MDN: Asynchronous JavaScript.

Synchronous vs asynchronous

Imagine asking for data from a server. Synchronous code would conceptually wait for the operation before moving on. Asynchronous code starts the operation and allows other work to continue; your program later handles the result.

console.log("A");

setTimeout(() => {
  console.log("C");
}, 0);

console.log("B");

// A
// B
// C

The callback does not run immediately just because the delay is zero. It is scheduled for later.

Promises

A Promise represents the eventual result of an asynchronous operation. It can be pending, fulfilled or rejected. You can attach handlers with then(), catch() and finally(). MDN: How to use promises.

doSomethingAsync()
  .then(result => {
    console.log("Success:", result);
  })
  .catch(error => {
    console.error("Failed:", error);
  })
  .finally(() => {
    console.log("Finished");
  });

async and await

async functions always return a Promise. Inside an async function, await lets you write promise-based logic in a sequential-looking form. It does not make the network operation itself synchronous or freeze the browser.

async function loadProfile() {
  try {
    const response = await fetch("https://example.com/profile.json");

    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }

    const data = await response.json();
    return data;
  } catch (error) {
    console.error("Could not load profile", error);
    throw error;
  }
}

Handle errors intentionally. A failed request, invalid response or invalid JSON are different failure points and your interface should tell the user what they need to know.

fetch(): talk to a web resource

The Fetch API provides the browser interface for making HTTP requests. It returns a Promise that fulfills with a Response. You then inspect the response and read its body as JSON, text or another supported format. MDN: Using Fetch · WHATWG Fetch Standard.

async function loadProducts() {
  const response = await fetch("/products.json");

  if (!response.ok) {
    throw new Error(`Request failed: ${response.status}`);
  }

  return response.json();
}

Important: a completed network request is not automatically a successful application result. Check response.ok or the status before treating the response as valid.

Loading, success and error states

A good interface represents the lifecycle of an asynchronous task. At minimum, think about:

  1. Idle: nothing is happening.
  2. Loading: work has started.
  3. Success: useful data arrived and was processed.
  4. Error: something failed and the user needs a useful message.

This is a simple idea, but it prevents a huge class of confusing interfaces.

Run independent work together

If two asynchronous operations do not depend on each other, starting them one after another can unnecessarily increase waiting time. Promise.all() lets you wait for several promises together.

const [profile, lessons] = await Promise.all([
  fetch("/profile.json").then(r => r.json()),
  fetch("/lessons.json").then(r => r.json())
]);

Use sequential await when the second operation needs the result of the first. Use concurrency when the operations are independent.

Cancel work when you no longer need it

Some browser operations can be cancelled with AbortController. This matters when a user changes a search query before an earlier request finishes or when a component/page no longer needs an operation.

const controller = new AbortController();

fetch("/search?q=javascript", {
  signal: controller.signal
});

// Later, when the request is no longer needed:
controller.abort();

Cancellation is about resource management and correct application behaviour, not just speed.

One rule to remember: await makes your code easier to read; it does not magically make a slow operation fast. Design the surrounding interface so the user knows what is happening.
06 · Capstone lab

Build a real browser application.

Your capstone is a small Learning Dashboard. It should combine the four areas of this module without using a framework.

Part A — Build the interface

  1. Create module-03-capstone/.
  2. Create index.html, styles.css and app.js.
  3. Add a form for adding a learning item: title, category and estimated minutes.
  4. Add a list that displays the saved learning items.
  5. Add controls to mark an item complete and remove it.
  6. Add an area showing total items, completed items and completion percentage.

Part B — Make the DOM dynamic

  1. Read the form values on submit.
  2. Validate the fields.
  3. Create the new item as a JavaScript object.
  4. Store items in an array.
  5. Render the array into the page.
  6. Use event delegation for actions inside the item list.
  7. Keep rendering separate from data-changing functions.
Target architecture:
user action → state change → render → browser displays new state

Part C — Remember the data

Use localStorage so closing and reopening the page does not destroy the learning list. Convert your array to JSON when storing it and parse it when reading it.

Test empty storage, existing storage and corrupted storage. Your application should fail gracefully instead of becoming unusable.

Part D — Add asynchronous data

Create a small local lessons.json file containing example lessons. Load it with fetch() when the page starts. Show a loading state, then render the lessons. If the request fails, show an understandable error and keep the manually created learning list usable.

Part E — Test the failure paths

  1. Submit an empty form.
  2. Enter invalid numbers.
  3. Add several items.
  4. Mark different items complete.
  5. Reload the page and verify persistence.
  6. Temporarily break the JSON path and observe the Network panel.
  7. Temporarily introduce a JavaScript error and inspect the Console.
  8. Use a slow network simulation if your browser supports it and inspect the loading state.
  9. Cancel or ignore an obsolete request if you implement search.

Part F — Explain your own code

Before you call the capstone complete, explain these without notes:

  1. Where does your application state live?
  2. Which function changes the state?
  3. Which function renders the state?
  4. What event starts the form workflow?
  5. Why did you use event delegation?
  6. What happens if localStorage contains invalid JSON?
  7. What happens when the JSON request returns 404?
  8. Why do you check response.ok?
  9. What happens while the request is still pending?
