01 · AI-assisted development

Make the developer faster without making the codebase mysterious.

AI coding tools are most useful when you give them a well-defined task, enough repository context, and a way to verify the result. The engineering loop remains: understand → plan → implement → inspect → test → review. AI can accelerate several steps, but it does not remove the need to understand what changed.

Good delegation

Ask for a focused change: explain the goal, relevant files, constraints, expected behavior, and tests. Small tasks are easier to review than a vague request to “build everything.”

Repository context

Give the model the contracts it actually needs: types, interfaces, database schema, existing patterns, error behavior, and acceptance criteria.

Verification

Read generated code, run the type checker, run tests, inspect the diff, and exercise the feature. Generated code is proposed code until you verify it.

Use AI to learn

Ask for explanations, alternatives, test cases, debugging hypotheses, documentation drafts, and trade-offs. Prefer understanding over blindly accepting output.

Engineering rule: if you cannot explain the generated code well enough to maintain it, the task is not finished.

A strong AI coding request

Goal:
Add a lesson-search feature.

Context:
The app uses Next.js + TypeScript. Lessons come from PostgreSQL.

Constraints:
Keep the existing component API. Do not change the database schema.

Acceptance criteria:
- Search by lesson title.
- Empty state when nothing matches.
- Keyboard-accessible input.
- Add tests for matching and no-result cases.

Before changing code:
Explain the files you expect to change and why.

This format creates an explicit contract. It also gives you something concrete to review when the model proposes a change.

02 · Model APIs

Connect your application to a model through a server boundary.

A model API is a network service your application calls to request model work. The model can generate text, analyze inputs, produce structured output, or select tools depending on the provider and model. Your backend owns the API key and controls what information and capabilities reach the model.

Do not place a provider secret in browser JavaScript. Keep provider credentials on the server, apply your own authentication and authorization, validate inputs, control data exposure, and return only the result your UI needs. OpenAI's current API documentation likewise states that API keys are secrets and should be loaded securely on the server rather than exposed in client-side code. OpenAI API Reference

Minimal server-side request

import OpenAI from 'openai';

const client = new OpenAI();

const response = await client.responses.create({
  model: 'YOUR_MODEL',
  input: 'Explain SQL joins to a beginner.'
});

return response.output_text;

The exact model identifier, SDK, limits, and pricing are provider-specific and change over time. Keep those details in configuration rather than scattering them through your application.

Streaming and latency

For long generated responses, streaming can let the interface display output progressively rather than waiting for the entire response. Treat streaming as a user-experience and transport decision, not as proof that the model is “thinking live.” Your application still needs cancellation, timeout, error, and partial-response handling.

Structured output

When application code needs machine-readable data, do not rely on the model merely being told “return JSON.” Use a supported structured-output mechanism and validate the result at the application boundary. OpenAI's current API reference documents JSON Schema-based Structured Outputs with strict schema adherence for supported models. Responses API reference

type LessonSummary = {
  title: string;
  difficulty: 'beginner' | 'intermediate' | 'advanced';

03 · AI features

Turn model capability into product behavior.

A useful AI feature has a defined job, a bounded input, a useful output, and a failure strategy. Start with the user problem—not “where can we add a chatbot?”

Summarization

Turn long lesson content into a short study brief while preserving links back to the source material.

Classification

Assign a known category such as difficulty, topic, or content type using a controlled schema.

Generation

Create drafts, examples, explanations, or practice questions with clear boundaries and review.

Retrieval

Find relevant application data or documents first, then provide selected context to the model instead of assuming model memory contains your private data.

Tool calling

A model can select a tool your application exposes, such as searchLessons or getProgress. The important boundary is that the model chooses an action while your application remains responsible for validating arguments and enforcing authorization before execution.

const tools = {
  searchLessons: {
    description: 'Search lessons by title',
    parameters: {
      type: 'object',
      properties: { query: { type: 'string' } },
      required: ['query']
    }
  }
};
Never confuse tool selection with permission. A model requesting deleteUser does not mean the application should execute it. Your normal authorization rules must remain in force.

RAG / retrieval-augmented generation

For knowledge that belongs to your application, a common architecture is retrieval first, generation second: retrieve relevant records or documents, provide only the necessary context, then generate an answer grounded in that context. Retrieval quality becomes part of the feature's correctness.

Cost, context, and latency

Every AI request has engineering constraints. Long prompts increase input volume; long outputs increase latency and cost; repeated context can be wasteful; unnecessary model calls can make a feature slow. Set practical limits, truncate or retrieve selectively, cache where appropriate, and choose a model based on the actual task rather than assuming the largest model is required.

04 · Evaluation

AI features need tests that understand variability.

Traditional software tests often expect one exact output. Model output can vary, so AI applications need a combination of deterministic checks and evaluation datasets. Define what “good” means before optimizing prompts.

Build an evaluation set

  1. Collect representative user inputs.
  2. Include easy, normal, ambiguous, and adversarial cases.
  3. Define expected properties rather than demanding identical wording.
  4. Measure accuracy, relevance, groundedness, refusal behavior, latency, and cost where applicable.
  5. Run the set whenever prompts, models, retrieval, tools, or safety logic change.

Separate application correctness from model quality

LayerQuestion
Input validationDid we accept only data the feature is designed to handle?
AuthorizationWas the user allowed to access the underlying information?
RetrievalDid we select relevant, permitted context?
Model outputDid the response satisfy the quality and safety criteria?
Output handlingDid the application safely validate and render the result?

Regression thinking

Model snapshots, prompts, retrieval logic, tool definitions, and provider behavior can change. Keep representative evaluations so you can detect regressions rather than discovering them through users. OpenAI's current API documentation also recommends evals and pinned model versions when consistent behavior matters because model behavior can change between snapshots. OpenAI API Reference

05 · Responsible use

Design the risk controls into the system.

Responsible AI is not a final checkbox. It is an engineering discipline covering data, model behavior, security, evaluation, user expectations, and operational monitoring. NIST's Generative AI Profile describes AI risk management across the lifecycle, while OWASP's 2025 LLM guidance highlights application-specific risks such as prompt injection, sensitive information disclosure, supply-chain issues, data/model poisoning, and improper output handling. NIST GenAI Profile · OWASP GenAI Top 10

Prompt injection

Treat external content as untrusted data. Do not let retrieved text or user content silently redefine application instructions or permissions.

Data exposure

Minimize sensitive data sent to models. Apply authorization before retrieval and avoid putting secrets, credentials, or unnecessary personal data into prompts.

Output handling

Model output is untrusted input. Validate structured results, escape rendered content, and never execute generated code or commands merely because the model produced them.

Human oversight

For consequential actions, provide review, clear user expectations, auditability, and an easy path to reject or correct AI output.

Security boundary: an LLM is not an authorization system, database constraint, input validator, or source of truth. Keep those responsibilities in deterministic application code.

Responsible AI checklist

  • Define the feature's purpose and failure modes.
  • Minimize data sent to the model.
  • Keep secrets server-side.
  • Authenticate and authorize before accessing private data.
  • Validate tool arguments and structured outputs.
  • Test prompt-injection and data-exfiltration scenarios.
  • Provide appropriate human review for consequential actions.
  • Log enough information to investigate failures without unnecessarily storing sensitive content.
  • Tell users when AI is being used when that context matters.
  • Monitor quality, cost, latency, and safety after release.

Build an AI Learning Coach.

Extend the Learning Hub from Modules 07–10 with one bounded AI feature: a lesson coach that can answer questions using permitted lesson content, create a short study plan, and suggest the next lesson.

Required behavior

  1. Create a server-side AI route; never expose the provider API key to the browser.
  2. Accept a learner question with explicit size limits.
  3. Verify the learner can access the selected lesson.
  4. Retrieve only the lesson context needed for the request.
  5. Ask the model for a bounded response.
  6. Return a typed result with a clear source/context boundary.
  7. Handle model timeout, refusal, empty retrieval, and provider errors.
  8. Add evaluation cases for correct answers, unsupported questions, prompt injection, and private-data requests.
  9. Measure latency and model usage.
  10. Document what the AI can and cannot do.

Deliberate failure drills

  • Put a fake secret in lesson content and verify it is not returned as a hidden application secret.
  • Ask the model to ignore the application's rules through lesson text and verify the application still enforces authorization.
  • Make the model return malformed structured data and verify the server rejects it safely.
  • Force a provider timeout and verify the UI shows a useful retry state.
  • Ask for a lesson the learner cannot access and verify the request is rejected before model invocation.
Completion standard: the feature is not complete when the model produces impressive text. It is complete when the whole system behaves predictably when the model is correct, wrong, unavailable, manipulated, expensive, or slow.
Agents & tool workflows

An agent is an application loop, not a magic permission layer.

From one model call to a controlled loop

An agentic workflow typically lets a model decide whether to call one or more application tools, receives the tool result, and continues until a stopping condition is reached. The application owns the tools, validation, authorization, state and limits.

User request
   ↓
Application policy
   ↓
Model
   ↓
Validated tool request
   ↓
Authorization check
   ↓
Tool execution
   ↓
Sanitized result → Model → Final response

Never interpret “the model selected this tool” as permission to execute it. A tool must enforce its own authorization and input constraints.

Agent safety controls

Tool allowlist

Expose only the operations the workflow genuinely needs.

Argument validation

Validate every model-produced argument against a strict schema.

Execution limits

Bound tool calls, tokens, time, cost and recursion/iteration count.

Auditability

Record important tool calls and outcomes without logging secrets or unnecessary sensitive data.

Know when not to use an agent

If a deterministic function, workflow or state machine can solve the problem reliably, prefer that simpler mechanism. Agentic loops add latency, cost and additional failure modes. Use them where flexible planning or tool selection creates a real product benefit.
