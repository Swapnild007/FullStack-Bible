Module 02 · Build the web

Give the web structure, style and behaviour.

This is where you start building. You will learn HTML to describe what a page means, CSS to control how it looks and adapts, JavaScript to make it respond, and accessibility so people can actually use what you build.

The mental model

Four layers. One web page.

A browser can display a page because different technologies have different jobs. HTML gives content and structure meaning. CSS controls presentation and layout. JavaScript can respond to user actions and change the page. Accessibility makes sure the structure and interaction remain usable by people with different abilities and different ways of accessing the web. MDN's core curriculum follows this same progression, beginning with semantic HTML, CSS fundamentals and accessibility. MDN Core learning modules.

HTML

“What is this?” A heading, paragraph, image, link, list, navigation area, article or form control.

CSS

“How should this appear?” Color, type, spacing, size, layout, responsive behaviour and visual states.

JavaScript

“What should happen?” Read information, make decisions, respond to actions and update the page.

Accessibility

“Can different people use it?” Keyboard access, meaningful structure, labels, alternatives and understandable interaction.

Core rule: do not use JavaScript to replace something HTML already provides. Do not use CSS to communicate meaning that belongs in HTML. Build the correct structure first, then style it, then add behaviour where it is genuinely needed.
01 · HTML

Build the meaning of the page.

HTML is the technology used to define the content and structure of websites. Correct HTML is not just about making text appear on screen; it gives the content meaning that browsers, assistive technologies and other systems can understand. MDN: Structuring content with HTML.

Start with the document

An HTML document has a predictable foundation. The doctype tells the browser to use modern HTML parsing rules. The html element contains the document. The head contains information about the document that is not normally displayed as page content. The body contains the content people interact with.

<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>My first website</title>
  </head>
  <body>
    <h1>My first website</h1>
    <p>I am learning to build for the web.</p>
  </body>
</html>

The lang value tells browsers and assistive technologies what language the document uses. The viewport setting helps the page behave correctly on mobile screens. The title identifies the document in browser tabs, history and other browser interfaces.

Elements, tags and attributes

An element is a piece of HTML with a particular meaning. Many elements have an opening tag, content and a closing tag. An attribute adds information to an element.

<a href="https://example.com">Visit the site</a>

<img src="portrait.jpg" alt="A person standing outdoors">

In the link, href says where the link goes. In the image, src identifies the image file and alt provides a text alternative. Learn to read markup from left to right: element, information about that element, then its content.

Headings create a content structure

Use headings to describe the hierarchy of your content. A page normally has one main heading for its primary subject, followed by lower-level headings for sections and subsections. Choose a heading because of its meaning, not because a browser makes it look large.

<h1>Learning web development</h1>
  <h2>HTML</h2>
  <h2>CSS</h2>
    <h3>Layout</h3>
  <h2>JavaScript</h2>

CSS can make any heading look large or small. The HTML should still describe the actual hierarchy.

Text, lists and links

Use paragraphs for paragraphs. Use unordered lists when the order does not matter and ordered lists when sequence matters. Use links for navigation to another location or resource.

<p>HTML describes the structure of a page.</p>

<ul>
  <li>HTML</li>
  <li>CSS</li>
  <li>JavaScript</li>
</ul>

<a href="about.html">About this project</a>

Good link text tells people where the link goes. “Read the accessibility guide” is more useful than a page containing five links that all say “click here”.

Images and alternative text

Images need a purpose. If an image communicates information, provide an appropriate text alternative. If an image is purely decorative and adds no useful information, its alternative text can be empty so assistive technology can ignore it.

<img src="team.jpg" alt="The product team standing together in the office.>

<img src="decorative-line.svg" alt="">

Do not write “image of” as a habit. Describe the useful meaning. For a photograph of a person giving a talk, “Priya explains the new product to the team” may be useful; “photo of Priya” may not be enough if the action matters.

Semantic HTML: choose the element that matches the job

Semantic means that the element communicates what the content is. Common structural elements include header, nav, main, section, article, aside and footer. These are not magic styling boxes. They communicate the role of parts of a page.

For an action, use a button. For navigation to another location, use an a link. For a form control, use the appropriate native input element and label. Avoid making a generic div pretend to be a button with JavaScript when the browser already provides a real button.

Forms are part of the web's structure

Forms collect information and provide controls for interaction. Start with the native controls before trying to customise them.

<form>
  <label for="email">Email address</label>
  <input id="email" name="email" type="email" required>

  <button type="submit">Subscribe</button>
</form>

The label tells the user what the input is for. The input type communicates what kind of value is expected. The required attribute lets the browser participate in basic validation. The button is keyboard-accessible and behaves like a button without requiring JavaScript.

MDN's HTML documentation covers forms, validation and the broader HTML element set. MDN: HTML.

HTML debugging

When HTML behaves strangely, look for mismatched tags, incorrect nesting, missing quotes, incorrect attribute names and paths that point to files that do not exist. Use the browser inspector from Module 01 to compare the source you wrote with the structure the browser created.

02 · CSS

Turn structure into an interface.

CSS controls presentation and layout: fonts, color, spacing, sizing, columns, positioning, responsive behaviour and more. MDN's CSS fundamentals begin with applying CSS to HTML, selectors, states, shorthand, functions and other core syntax. MDN: CSS styling basics.

The basic CSS sentence

p {
  color: #333;
  font-size: 1rem;
  line-height: 1.6;
}

The selector says which elements you want to affect. The declarations inside the braces say what should change. Each declaration has a property and a value. CSS contains many properties, but the important skill is learning how to reason from “which element?” to “which property?”

Selectors: choose what you mean

Start with simple selectors: an element selector such as p, a class selector such as .card, and an ID selector such as #profile. Classes are generally the most reusable way to describe a visual pattern.

p { color: #444; }
.card { padding: 24px; }
#profile { max-width: 700px; }

You can also combine selectors when the relationship matters. Do not make selectors unnecessarily complicated. Simple rules are easier to understand, override and maintain.

The box model

Every visible element can be understood as a box. The content sits inside padding. A border can surround the padding. Margin creates space outside the border. This model explains many beginner layout problems.

.card {
  width: 320px;
  padding: 20px;
  border: 1px solid #ddd;
  margin: 20px;
}

A practical habit is to use box-sizing: border-box so declared widths include padding and borders. This makes many layouts easier to reason about.

Typography, color and spacing

Good CSS is not a collection of random values. Establish a visual system. Choose readable type, a small set of colors, consistent spacing and sensible line lengths. Relative units such as rem, percentages and flexible layout values are often useful because they adapt better than fixed pixel measurements alone.

Do not use color as the only way to communicate meaning. A red field for an error should also have text or another clear indication. This matters for people who cannot distinguish the colors and for people using the page in difficult lighting.

Flexbox: arrange things in a row or column

Flexbox is designed for arranging items along one direction at a time. It is useful for navigation bars, button groups, cards in a row and many other components.

.actions {
  display: flex;
  gap: 12px;
  align-items: center;
  justify-content: space-between;
}

Learn the idea rather than memorising a recipe: the parent becomes the layout container and its direct children become the items being arranged.

Grid: build two-dimensional layouts

CSS Grid is useful when rows and columns both matter. It can create cards, page regions and more structured layouts.

.cards {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 20px;
}

Do not force Grid everywhere. Use the simplest layout tool that describes the relationship you need.

Responsive design

A web page is not tied to one screen size. Responsive design lets the layout adapt to available space. Start with the content and let the layout change when the screen becomes too narrow.

.cards {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 20px;
}

@media (max-width: 700px) {
  .cards {
    grid-template-columns: 1fr;
  }
}

Use your browser's responsive tools from Module 01 to test the transition. Then test with real devices later because emulation is useful but not identical to every physical environment. MDN's CSS layout curriculum covers responsive designs and modern layout tools. MDN: CSS layout.

States and interaction

CSS can respond to interaction without JavaScript. Common states include :hover, :focus, :focus-visible, :active and :disabled.

button:focus-visible {
  outline: 3px solid #007aff;
  outline-offset: 3px;
}

Never remove focus indicators without replacing them with something equally clear. Keyboard users need to know which control is currently active.

CSS rule: build a layout that works before decorating it. If removing every color, shadow and animation makes the page impossible to understand, the structure was doing too little work.
03 · JavaScript basics

Make the page respond.

JavaScript is a programming language that can run in browsers and elsewhere. At this stage, you need the basic programming ideas and the ability to connect them to a web page. The goal is not to memorise hundreds of methods; it is to learn how data, decisions, reusable instructions and events fit together.

Values and variables

A value is information such as text, a number, a true/false value, or a collection of values. A variable gives you a name you can use to refer to a value. Use const when the variable name will not be reassigned, and let when it needs to be reassigned.

const learnerName = "Swapnil";
let lessonsCompleted = 2;
const isLearning = true;

lessonsCompleted = lessonsCompleted + 1;

JavaScript has more value types and rules than this simple example shows. Learn the distinction between the value itself and the name you use to refer to it.

Strings, numbers and true/false

const name = "Maya";
const age = 30;
const hasStarted = true;

console.log(name);
console.log(age + 1);
console.log(hasStarted);

Do not assume every value is text. A number can participate in arithmetic. A true/false value can control a decision. Understanding the type of your data prevents many beginner bugs.

Decisions with if

Programs often need to choose what to do. An if statement runs code when a condition is true. An else block can handle the other case.

const score = 82;

if (score >= 50) {
  console.log("Passed");
} else {
  console.log("Keep practising");
}

The condition is an expression that becomes true or false. Comparison operators such as ===, >, <, >= and <= help express those decisions.

Functions: give a task a name

A function is a reusable piece of code. It can receive information, perform work and return a result.

function greet(name) {
  return `Hello, ${name}!`;
}

const message = greet("Maya");
console.log(message);

Functions help you avoid repeating the same instructions and make your program easier to break into understandable pieces.

Arrays and objects

An array stores an ordered collection. An object groups related information using named properties.

const topics = ["HTML", "CSS", "JavaScript"];
console.log(topics[0]);

const learner = {
  name: "Maya",
  completed: 3
};

console.log(learner.name);

Arrays are useful when order matters. Objects are useful when several pieces of information describe one thing. You will use both constantly in later full-stack work.

Loops: repeat work without copying it

const topics = ["HTML", "CSS", "JavaScript"];

for (const topic of topics) {
  console.log(topic);
}

A loop lets a program perform an operation for each item in a collection. Learn to recognise when repetition is a problem your program should handle rather than something you should write manually three, ten or one hundred times.

The browser page and the DOM

The browser turns your HTML into a live document that JavaScript can inspect and change. This document is commonly called the DOM. You do not need to memorise its entire API yet. Start with selecting an element, reading information from it, changing text, changing classes and responding to user actions.

const heading = document.querySelector("h1");
heading.textContent = "I changed this with JavaScript";

This changes the current page in the browser. It does not automatically rewrite your HTML file on disk.

Events: react to what people do

An event represents something that happened, such as a click, a key press, a form submission or a page loading. JavaScript can listen for an event and run a function when it occurs.

const button = document.querySelector("button");
const message = document.querySelector("#message");

button.addEventListener("click", () => {
  message.textContent = "Thanks for clicking.";
});

Prefer real HTML controls for interaction. A real button can receive keyboard input and has browser behaviour already built in. JavaScript should add the behaviour you need rather than recreate basic browser functionality badly.

Debug JavaScript like a developer

When something fails, separate the possibilities: Did the script load? Did the selector find the element? Did the event happen? Did the function run? Did the data have the value you expected?

console.log("Script started");
console.log("Selected button:", button);
console.log("Current value:", score);

Use the Console and Sources/Debugger tools in your browser when appropriate. Read the error message, locate the file and line, reproduce the problem, then change one thing at a time.

Do not jump ahead yet: asynchronous JavaScript, promises, modules, APIs, advanced object behaviour and application architecture belong later in the roadmap. This module is about becoming comfortable writing small, understandable programs that control a page.
04 · Accessibility

Build so more people can use it.

Accessibility means designing and developing web content so people with disabilities can use it. W3C's Web Accessibility Initiative describes accessibility as a combination of content, browsers and other user agents, assistive technologies and the way people interact with the web. WCAG 2.2 provides an international technical standard organised around four principles: perceivable, operable, understandable and robust. W3C: Introduction to Web Accessibility · W3C: WCAG overview.

Accessibility starts in HTML

Use the right element for the job. Semantic HTML gives browsers and assistive technologies information about the purpose and structure of content. A native button is already keyboard-accessible. A native link already communicates navigation. A labelled input already gives assistive technology a name for the control.

MDN specifically identifies semantic HTML, useful alternative text, good link text, form labels, keyboard accessibility and sensible source order as important accessibility practices. MDN: HTML as a good basis for accessibility.

Keyboard access

Some people navigate without a mouse. Every important interactive control should therefore be reachable and usable with a keyboard. Try your own page using only Tab, Shift+Tab, Enter and the relevant arrow keys.

Watch for three problems: an element cannot receive focus, the focus order makes no sense, or the focus indicator is too difficult to see. Do not create a custom interaction until you understand how the native equivalent behaves.

Labels and forms

Every form control should have a clear accessible name. The simplest approach is usually a visible label connected to the input.

<label for="full-name">Full name</label>
<input id="full-name" name="full-name" autocomplete="name">

Placeholder text is not a replacement for a proper label. A placeholder can disappear when the user starts typing and can be difficult to perceive in some situations.

Images, icons and alternative text

Ask what the user needs to know from the image. If the image carries information, provide that information in text. If it is decorative, do not force a meaningless description into the experience. If an icon is the only visible part of a button, make sure the button still has an accessible name.

<button type="button" aria-label="Open menu">
  <span aria-hidden="true">☰</span>
</button>

Use ARIA carefully. It can help when native HTML cannot express a required interface pattern, but adding ARIA does not automatically make a component accessible. Native HTML should be your first choice.

Color, contrast and visible states

Text and controls must remain understandable. Do not make a link distinguishable only by color. Do not remove focus outlines just because they look less polished. Use sufficient contrast and make important states visible through more than one clue when needed.

WCAG 2.2 is organised under four broad principles: content should be perceivable, controls should be operable, information and operation should be understandable, and the implementation should remain compatible with current and future user agents. W3C: WCAG 2 at a Glance.

Motion should not become a barrier

Animations can make an interface feel alive, but some people prefer reduced motion. Respect the user's operating-system preference with prefers-reduced-motion and avoid animation that is unnecessary for understanding or completing a task.

@media (prefers-reduced-motion: reduce) {
  * {
    animation: none !important;
    transition: none !important;
  }
}

Test accessibility before calling a page finished

  1. Navigate the whole page with a keyboard.
  2. Confirm every important control has a visible focus state.
  3. Check headings and page landmarks for a sensible structure.
  4. Check every meaningful image for a useful alternative.
  5. Check every form field has a clear label.
  6. Check links describe their destination.
  7. Zoom the page and confirm content remains usable.
  8. Test a narrow viewport and a wide viewport.
  9. Use browser accessibility tooling where available.
  10. Fix the underlying HTML before reaching for complex ARIA solutions.
Accessibility is not a final polish step. Good HTML, clear content, keyboard-friendly controls and sensible structure should be built from the beginning. W3C treats accessibility as a shared system involving content, user agents and assistive technologies, not merely a visual checklist.
05 · Capstone

Build one small site from scratch.

Do not treat this as a code-copying exercise. Build it in stages and use the browser to inspect your work. Your finished project should be a small, responsive, accessible learner profile site.

Part A — HTML first

Create the project.

Make a folder named module-02-project with index.html, styles/style.css, scripts/app.js and an images folder.

Build meaningful structure.

Add a header, navigation, main content, an introduction section, a learning list, an image, a contact form and a footer.

Use native elements.

Use headings, paragraphs, lists, links, a real button, labelled inputs and the correct form elements.

Make the page understandable without CSS.

Temporarily disable CSS. The document should still have a sensible reading order and meaningful content.

Part B — CSS second

Set a foundation.

Choose readable typography, line height, page width, background and text colors.

Build spacing.

Use consistent padding, margin and gaps instead of random values on every element.

Build the layout.

Use Flexbox and/or Grid where the relationships call for them. Avoid absolute positioning for the entire page.

Make it responsive.

Test narrow and wide widths. Let the layout adapt rather than forcing desktop content into a tiny screen.

Part C — JavaScript third

Add one useful interactive feature: for example, a button that switches a learning status, a small character counter for a message field, or a menu that opens and closes.

The interaction must work with keyboard input and must have a clear visible state. Do not build a custom control if a native HTML control already does the job.

const button = document.querySelector("#status-button");
const status = document.querySelector("#status");

button.addEventListener("click", () => {
  const complete = status.dataset.complete === "true";
  status.dataset.complete = String(!complete);
  status.textContent = complete ? "In progress" : "Complete";
});

Part D — Accessibility pass

Use the keyboard only. Tab through every interactive element. Can you tell where you are? Can you activate every control? Are labels clear? Are images described appropriately? Does the page still make sense when zoomed? Does it remain understandable when color is not enough to communicate a state?

Part E — Break and repair

  1. Remove an image's alt and explain what changed.
  2. Remove a form label and inspect the difference.
  3. Change a real button into a generic div and observe what you have lost.
  4. Break a CSS file path and diagnose it using Network.
  5. Break a JavaScript selector and diagnose it using Console.
  6. Make a heading hierarchy confusing and then restore it.
  7. Fix each problem and write down the evidence that led you to the solution.
