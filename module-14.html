MODULE 14 · ADVANCED TOOLING

Make the codebase scale with the team.

Advanced Git, monorepos, shared packages, code quality and fast developer feedback loops.

1. Advanced Git

Go beyond add/commit/push. Learn interactive rebase for cleaning local history, cherry-pick for moving focused commits, bisect for locating regressions, and worktrees for parallel branches without repeatedly switching one working directory.

git rebase -i HEAD~5
git bisect start
git cherry-pick <commit>
git worktree add ../feature feature-x

2. Collaboration models

Compare trunk-based development with GitFlow. Understand short-lived branches, feature flags, small pull requests, squash merges, merge commits, release branches and rollback strategies. Choose a workflow based on deployment frequency and team constraints rather than fashion.

3. Monorepo architecture

A monorepo keeps multiple related packages in one repository. Typical packages include a web application, API, UI library, shared TypeScript types, configuration packages and tooling. The important skill is dependency boundaries: a shared package should have a clear public API and should not secretly depend on application internals.

apps/
  web/
  docs/
packages/
  ui/
  types/
  config-eslint/
  config-ts/

4. Workspace management

Learn npm or pnpm workspaces. Understand package names, workspace dependencies, lockfiles, hoisting/linking behaviour, scripts and package boundaries. pnpm workspaces and Turborepo are useful tools for larger JavaScript/TypeScript repositories.

5. Build orchestration

As repositories grow, running every task for every package becomes expensive. Learn task graphs, dependency-aware builds, caching, affected-project execution and remote caching. Treat caching as an optimization with correctness requirements: cache keys must represent all inputs that affect the output.

6. Code quality

  • ESLint catches classes of JavaScript/TypeScript problems.
  • Prettier standardizes formatting.
  • TypeScript strict checking catches type-level errors before runtime.
  • Biome is an alternative integrated formatter/linter toolchain.
  • Husky and lint-staged can run focused checks before commits.

Do not turn tooling into ceremony. Every check should prevent a real class of defect or reduce review cost.

7. Capstone — shared engineering platform

Convert a small application collection into a monorepo with a shared UI package, shared domain types, shared lint/TypeScript configuration, workspace scripts and dependency-aware CI. Document package boundaries and demonstrate that changing one package does not rebuild unrelated applications.

Stage checklist

Knowledge check

  1. When is interactive rebase useful?
  2. How does git bisect reduce regression-search time?
  3. What problem does a Git worktree solve?
  4. What makes a package boundary healthy?
  5. Why does a monorepo need task orchestration?
  6. What should a cache key contain?
  7. Why should lockfiles be committed?
  8. When should a team avoid adding another shared package?
