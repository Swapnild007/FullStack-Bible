01

Python mental model

Understand what Python code means before memorizing syntax.

Build from first principles

Python is an interpreted, dynamically typed, object-oriented language with a rich runtime. Names refer to objects; assignment binds a name to an object rather than copying a value in the way beginners often imagine. This mental model becomes important when working with mutable data structures and ML pipelines.

Core ideas

  • Objects, identity, type and value.
  • Name binding and references.
  • Expressions versus statements.
  • Mutable versus immutable objects.
  • Modules, packages and the Python runtime.
Think like an engineer: before debugging a result, ask what object each variable references, what type it has and which operation produced the current state.
Before moving on

Explain the difference between a variable name and the object it refers to, and demonstrate mutation with a list.

Types & control flow

Turn logic into deterministic programs.

Core ideas

  • Numbers, strings, booleans and None.
  • Comparisons and boolean logic.
  • if/elif/else decision structures.
  • for and while loops.
  • Comprehensions and iteration protocols.

03

Data structures

Choose representations based on operations and complexity.

Core ideas

  • Lists and dynamic arrays.
  • Tuples and immutable records.
  • Sets and membership.
  • Dictionaries and hash-based lookup.
  • Stacks, queues and deques.
  • Nested structures and data normalization.
Engineering trade-off: choosing a set instead of repeatedly scanning a list can change membership checks from linear search to expected constant-time lookup, subject to hashing assumptions.
Practice

Represent the same dataset using a list, dictionary and set. State which operations each representation makes convenient.

OOP & modules

Organize larger Python systems without creating unnecessary complexity.

Core ideas

  • Classes, instances and attributes.
  • Methods and encapsulation.
  • Inheritance versus composition.
  • Dataclasses and value objects.
  • Imports, packages and dependency boundaries.

Design principle: prefer composition when it expresses a system more clearly than a deep inheritance hierarchy. ML projects benefit from small components with explicit interfaces.

07

Algorithms

Move from writing code to designing procedures.

An algorithm is a finite procedure for transforming inputs into outputs. AI engineers need algorithmic reasoning because data preparation, search, optimization and inference all contain algorithmic structure.

Core ideas

  • Correctness and invariants.
  • Divide and conquer.
  • Greedy reasoning.
  • Dynamic programming intuition.
  • Graph traversal.
  • Hashing and lookup.
Practice

Implement linear search and binary search. State the precondition that binary search requires.

08

Complexity

Reason about time, memory and scalability.

Core ideas

  • Big-O notation and asymptotic growth.
  • Best, average and worst-case reasoning.
  • Time versus space trade-offs.
  • Amortized analysis intuition.
  • Why vectorization can change practical performance.
Example: scanning n records is O(n). Repeatedly scanning the same n records inside another loop can become O(n²). The mathematical growth rate matters more as data scales.
Practice

Analyze the complexity of three functions you write and explain which operation dominates runtime.

09

Recursion

Understand self-referential computation and its trade-offs.

Recursive algorithms solve a problem by reducing it to smaller instances of itself. Every correct recursive design needs a base case and a measure that moves toward that base case.

def factorial(n): if n <= 1: return 1 return n * factorial(n - 1)
Practice

Trace a recursive function by hand, identify its call stack and rewrite it iteratively. Explain the time and space implications.

11

Testing & debugging

Turn correctness into evidence.

Core ideas

  • Unit, integration and end-to-end tests.
  • Arrange–act–assert structure.
  • Boundary and negative cases.
  • Reproducible failures.
  • Debugging with tracebacks, breakpoints and minimal reproductions.
def clamp(x, low, high): if low > high: raise ValueError("invalid bounds") return max(low, min(x, high)) assert clamp(12, 0, 10) == 10
Practice

Write tests before fixing a deliberately broken function. Add a regression test so the same bug cannot silently return.

12

Git & AI-assisted engineering

Use version control and coding assistants without surrendering engineering judgment.

Core ideas

  • Repositories, commits, branches and diffs.
  • Small reversible changes.
  • Pull requests and code review.
  • Writing precise prompts for coding assistants.
  • Verify generated code with tests and documentation.
  • Never treat generated code as automatically correct.
AI workflow: specify → generate → inspect → test → benchmark → review → commit. The human engineer remains responsible for correctness, security and maintainability.
Mini-lab

Ask an AI coding assistant to implement a function, deliberately test edge cases, identify one weakness in the generated solution and improve it.

13

NumPy & vectorized computation

Transition from Python objects to numerical arrays.

Core ideas

  • Array shape, dtype and dimensionality.
  • Indexing, slicing and broadcasting.
  • Vectorized operations.
  • Matrix multiplication.
  • Reductions and axis semantics.
  • Memory layout and why array operations can outperform Python loops.
import numpy as np X = np.array([[1.,2.],[3.,4.]]) w = np.array([0.5,2.]) scores = X @ w print(scores)
Before moving on

Predict array shapes before executing operations and explain the difference between elementwise multiplication and matrix multiplication.

14

Engineering lab

Integrate programming, algorithms, testing and numerical computing.

Build

Create a small command-line data-analysis utility. It should load a CSV, validate its schema, calculate descriptive statistics, provide a search operation, write JSON output and expose a clean Python API.

Required engineering evidence

  • Clear project structure.
  • Type hints and documentation.
  • Unit tests including edge cases.
  • Complexity analysis for the search operation.
  • NumPy implementation for at least one numerical calculation.
  • Git history showing incremental commits.
  • README explaining design decisions.
Stage gate

You should be able to explain every important line, defend the data structure choices, demonstrate tests and describe where the program would fail at larger scale.

Stage 01 completion assessment

Completion requires implementation evidence, not passive reading.

  • Build a tested Python package from scratch.
  • Implement and analyze at least two algorithms.
  • Explain Big-O time and space complexity.
  • Use NumPy correctly for array-based computation.
  • Use Git for incremental, reviewable changes.
  • Use an AI coding assistant and independently verify its output.
  • Complete the engineering lab with documentation.

Required mindset: design → implement → test → measure → review → document.
