Problem vs algorithm vs program

Separate the problem specification from the procedure and its implementation.

FIRST PRINCIPLESWORKED EXAMPLEIMPLEMENTATIONMASTERY GATE

1. Why this matters

A problem describes what must be achieved. An algorithm describes a finite procedure that achieves it under stated assumptions. A program is an executable representation of that procedure plus the engineering needed to run it.

2. Formal model

For the problem 'determine whether a value occurs in a collection', linear search is an algorithm. A Python function using a loop is one program implementing it. Correctness belongs first to the algorithm and then to its implementation.

3. Worked example

For [7,4,9,2] and target 9, linear search checks 7, then 4, then 9 and stops. Each iteration advances through a finite collection.

4. Implementation

The implementation is intentionally small so the underlying concept remains visible.

def contains(items, target):
    for item in items:
        if item == target:
            return True
    return False

5. Execution trace

The invariant is that every examined element has been shown not to equal target. If target exists, it is eventually examined; otherwise the collection is exhausted.

6. Under the hood

Python supplies iteration and comparison semantics. The algorithm itself is language-independent, while the program is one concrete implementation.

7. Complexity / engineering implications

Worst-case time O(n), best-case O(1), additional space O(1). Bounds depend on the representation and operation being analyzed.

8. Failure modes & misconceptions

Do not claim correctness because a few examples passed. Reason about all inputs satisfying the specification.

9. Engineering lab

Write the specification, pseudocode, invariant and implementation for linear search. Test empty, first, last and absent targets.

10. Mastery gate

Explain what changes when the same problem is solved with binary search and identify its additional precondition.
