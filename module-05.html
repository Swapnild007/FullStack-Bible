Module 05 · Add TypeScript

Make JavaScript easier to reason about.

You already know JavaScript. TypeScript adds a static type system that checks your code before it runs. The goal is not to replace JavaScript; it is to make the shape of your data and the contracts between pieces of code clearer, earlier, and easier for tools to verify.

The mental model

TypeScript checks your JavaScript before runtime.

The official TypeScript Handbook describes TypeScript as a static typechecker for JavaScript programs. That means the type system analyzes source code before the program runs. It can report that a function is being called with the wrong kind of value, that a property may not exist, or that a case has not been handled. It does not make JavaScript runtime validation disappear: data coming from users, files, databases, APIs, or network responses still has to be treated as runtime data.

JavaScript

The language that executes at runtime. TypeScript builds on JavaScript rather than replacing its runtime model.

Types

Descriptions of the values your program expects: strings, numbers, objects, arrays, unions, functions and more.

Inference

TypeScript can often work out a value's type without an annotation, reducing unnecessary typing.

Narrowing

Runtime checks such as typeof, equality, in, and discriminated unions let TypeScript refine a broader type.

Core idea: TypeScript is most useful when types describe real boundaries in your program. Do not add annotations simply to make the file look “typed”.
01 · Types

Describe the values your program can work with.

Start with the types you already met in JavaScript, then learn how TypeScript combines them. TypeScript can infer many types automatically, so explicit annotations should be used where they improve clarity or define an important contract. Official Handbook: Everyday Types.

Primitive types

Common primitives include string, number, boolean, bigint, symbol, null and undefined. The type describes what operations are valid for that value.

let learnerName: string = "Swapnil";
let completed: boolean = false;
let score: number = 92;

If a variable is initialized directly, TypeScript can usually infer the type:

const moduleNumber = 5; // number
const title = "Add TypeScript"; // string

Arrays and tuples

An array type describes what every item in the collection can be. A tuple describes a fixed-position structure where each position has a known type.

const scores: number[] = [80, 91, 88];
const tags: Array<string> = ["web", "typescript"];

const result: [boolean, number] = [true, 94];

Use tuples when the positions have meaning. Use arrays when you have a collection of similarly shaped values.

Union types

A union says that a value can be one of several types. Your code must handle the possibilities before using an operation that only works for one member.

function formatId(id: string | number): string {
  if (typeof id === "number") {
    return id.toString();
  }
  return id.toUpperCase();
}

This is the beginning of narrowing: the declared type is broad, while the code path can establish a more specific type.

Literal types

A type can describe specific allowed values rather than every value of a primitive type. This is useful for states, options, and small controlled vocabularies.

type Status = "idle" | "loading" | "success" | "error";

let status: Status = "idle";
status = "success";
// status = "finished"; // TypeScript error

Aliases and interfaces

A type alias gives a reusable name to a type. Interfaces are another way to describe object shapes and can be extended or merged in ways that are useful in larger codebases.

type Lesson = {
  id: string;
  title: string;
  completed: boolean;
};

interface User {
  id: string;
  name: string;
}

Do not turn the choice between type and interface into a rule you memorize blindly. Learn the capabilities of both and follow the conventions of the codebase you join.

unknown versus any

unknown means “we do not know the type yet” and forces you to check before using the value. any effectively opts out of type checking for that value. For data crossing an untrusted or dynamic boundary, unknown is usually the safer starting point.

function printValue(value: unknown) {
  if (typeof value === "string") {
    console.log(value.toUpperCase());
  }
}
02 · Functions & objects

Make the contracts between pieces of code explicit.

Typed function parameters and returns

A function type describes its parameters and return value. This makes incorrect calls visible during development and documents the function's contract for editors and future readers.

function calculateProgress(done: number, total: number): number {
  if (total === 0) return 0;
  return Math.round((done / total) * 100);
}

TypeScript can infer a return type from the implementation, but explicit return types can be valuable at important boundaries and for public functions because they make an intended contract visible.

Optional and default parameters

function greet(name: string, prefix = "Hello"): string {
  return `${prefix}, ${name}`;
}

function findLesson(id: string, includeArchived?: boolean) {
  // includeArchived is boolean | undefined
}

An optional parameter can be absent, so its type includes undefined. Treat that possibility intentionally.

Object shapes

Objects are where TypeScript becomes especially useful. You can describe exactly which properties exist, their types, and whether they are optional or read-only.

type Lesson = {
  readonly id: string;
  title: string;
  completed?: boolean;
};

const lesson: Lesson = {
  id: "js-05",
  title: "TypeScript"
};

readonly is a compile-time restriction. It does not freeze the JavaScript object at runtime.

Function types

type Formatter = (value: number) => string;

const formatScore: Formatter = score => `${score}%`;

function applyFormat(value: number, formatter: Formatter) {
  return formatter(value);
}

Functions are values in JavaScript, so TypeScript can describe them just as it describes objects and primitives.

03 · Narrowing

Let the code prove which type you have.

TypeScript uses control-flow analysis to refine union types. The official Handbook calls this process narrowing. Checks such as typeof, in, instanceof, equality comparisons, and user-defined type predicates can provide evidence about the value's actual shape. Official Handbook: Narrowing.

typeof and equality checks

function display(value: string | number) {
  if (typeof value === "string") {
    return value.toUpperCase();
  }

  return value.toFixed(2);
}

Inside the first branch, TypeScript knows the value is a string. After the branch, it can reason about the remaining possibility.

Discriminated unions

A shared literal property can identify which member of a union you have. This pattern scales well for application state and event-like data.

type State =
  | { status: "loading" }
  | { status: "success"; data: string[] }
  | { status: "error"; message: string };

function render(state: State) {
  switch (state.status) {
    case "loading": return "Loading…";
    case "success": return state.data.join(", ");
    case "error": return state.message;
  }
}

Exhaustiveness

When every member of a union must be handled, an exhaustive check can make future changes safer. If a new state is added but not handled, the compiler can expose the missing case.

function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${value}`);
}
04 · Generics

Write reusable code without throwing away type information.

Generics let a function, type, or component work with different types while preserving the relationship between its inputs and outputs. The TypeScript Handbook presents generics as a way to build reusable components with well-defined APIs. Official Handbook: Generics.

The simplest generic

function identity<T>(value: T): T {
  return value;
}

const text = identity("hello"); // string
const count = identity(42);      // number

The important relationship is that the type accepted by the function is connected to the type returned by the function.

Generic collections

function first<T>(items: T[]): T | undefined {
  return items[0];
}

const firstLesson = first(["HTML", "CSS"]); // string | undefined
const firstScore = first([90, 84]);           // number | undefined

Notice that the result keeps the element type. A generic is not simply a fancy replacement for any.

Constraints

Sometimes a generic needs a known capability. An extends constraint limits which types can be supplied.

function getLength<T extends { length: number }>(value: T): number {
  return value.length;
}

getLength("hello");
getLength([1, 2, 3]);

Generic object types

type ApiResponse<T> = {
  data: T;
  ok: boolean;
  message?: string;
};

type LessonResponse = ApiResponse<Lesson[]>;

This pattern becomes useful when several API responses share a wrapper but carry different data.

05 · Type-safe code

Use the type system at the boundaries that matter.

Type safety is not about covering every line with annotations. It is about making invalid states harder to express, catching mistakes before runtime, and making interfaces between modules easier to understand. Type inference, narrowing, utility types and compiler options are part of the practical TypeScript toolkit.

Prefer inference

Let TypeScript infer obvious local values. Add an annotation when it clarifies an API, variable boundary, or intended constraint.

Model real states

Use unions and discriminated unions when a value has a finite set of meaningful states.

Protect boundaries

Network data, user input and external JSON are runtime data. Types alone cannot prove that external data is valid.

Keep checks strict

Use the compiler to expose unsafe assumptions instead of silencing errors with broad casts.

Utility types

TypeScript provides built-in utility types for common transformations. Examples include Partial, Pick, Omit, Record, ReturnType and Awaited. Learn them after you understand ordinary object and function types.

type Lesson = {
  id: string;
  title: string;
  completed: boolean;
};

type LessonUpdate = Partial<Pick<Lesson, "title" | "completed">>;

Official Handbook: Utility Types

Type assertions are not validation

const raw: unknown = getExternalData();

// A cast does not check the runtime value:
const lesson = raw as Lesson;

A type assertion tells the compiler how you want to treat a value; it does not transform or validate that value at runtime. For external data, perform an actual runtime check or use a validation library when appropriate.

Compiler thinking

TypeScript's compiler options determine how aggressively the type checker protects your code. A strict configuration catches more unsafe assumptions. When you encounter an error, first understand what the checker is telling you; do not immediately suppress it.

// tsconfig.json
{
  "compilerOptions": {
    "strict": true
  }
}

The exact project configuration can vary, but learning with strict checking gives you useful feedback about nullability, function parameters, and other assumptions.

Capstone lab

Convert a small JavaScript app into TypeScript.

Take the Module 03 learning dashboard and migrate the core logic to TypeScript. The point is not to mechanically rename files. You will identify the data your application actually handles, define its contracts, and make the compiler expose weak assumptions.

Build: Typed Learning Dashboard

  1. Create a new module-05-capstone project.
  2. Move the application's lesson data into typed objects.
  3. Create Lesson, LessonState, and API-response types.
  4. Type the functions that create, update, remove, filter, and render lessons.
  5. Use a discriminated union for loading, success, and error state.
  6. Write one generic helper such as first<T> or a typed response wrapper.
  7. Treat fetched JSON as untrusted runtime data rather than assuming a cast makes it safe.
  8. Enable strict compiler checking and fix the errors without hiding them.
  9. Run the application and compare its behaviour with the JavaScript version.
type Lesson = {
  id: string;
  title: string;
  completed: boolean;
};

type LessonState =
  | { status: "loading" }
  | { status: "success"; lessons: Lesson[] }
  | { status: "error"; message: string };

function completedCount(lessons: Lesson[]): number {
  return lessons.filter(lesson => lesson.completed).length;
}
Challenge: deliberately introduce three type errors: pass the wrong argument to a function, misspell an object property, and add an impossible state. Read the compiler messages, fix the underlying model, then run the application to confirm that runtime behaviour still works.
